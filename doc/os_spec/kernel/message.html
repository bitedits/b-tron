1.2 Повідомлення管理

1.2.1 Процеси та потоки間Повідомлення

Процеси та потокиにはПовідомленняキューが付属しており、 このПовідомленняキューを経由してПроцеси та потоки間Повідомлення通信が行なわれる。 この機能は、Процеси та потоки間でのアプリケーションПовідомленняの通信だけではなく、 子Процеси та потокиの終了Повідомлення等のシステムでの用途にも使用される。 このため、いくつかのПовідомленняの形式はシステムで定義されている。

Повідомленняは、Процеси та потокиに付属しているПовідомленняキューに送られ、 送信先はそのПроцеси та потоки ID により指定される。 また送信元も送信Процеси та потокиのПроцеси та потоки ID により識別される。

1 つのПовідомленняは以下の構造を持ち、msg_type により 1 〜 31 の 31 種のタイプに分けられている。 さらに各タイプにビット対応したタイプマスクにより、 Повідомленняの受信 / クリアにおいて、対象とするПовідомленняのタイプ ( 複数 ) を指定できるようになっている。 

typedef union {
    struct {
        W   pid;
        W   code;
    } ABORT;        /* Процеси та потокиの異常終了Повідомлення */
    struct {
        W   pid;
        W   code;
    } EXIT;         /* Процеси та потокиの正常終了Повідомлення */
    struct {
        W   pid;
        W   code;
    } TERM;         /* Процеси та потокиの強制終了Повідомлення */
    struct {
        W   code;
    } TMOUT;        /* タイムアウトПовідомлення */
    struct {
        W   code;
    } SYSEVT;       /* システムイベントПовідомлення */
    struct {
        UB  msg_str[32];
    } ANYMSG;       /* その他一般 */
} MSGBODY;

typedef struct message {
    W       msg_type;   /* Повідомленняタイプ */
    W       msg_size;   /* Повідомлення本体サイズ(バイト) */
    MSGBODY msg_body;   /* Повідомлення本体 */
} MESSAGE;

Процеси та потокиのПовідомленняキューには他Процеси та потокиからのПовідомлення以外にも自Процеси та потокиから送信したПовідомленняも ( 送信先が自Процеси та потокиの場合 ) 入り、 この種のПовідомленняとしてはタイムアウトПовідомленняがある。 なお、子Процеси та потокиが終了した場合の終了ПовідомленняもこのПовідомленняキューに入る。

Повідомленняキューは FIFO であり、必ず送信順に入れられる。 送信時に相手のПовідомленняキューがフルの場合は、 キューに空きができるまで待つか、エラーリターンするかを指定できる。

通常は、受信したПовідомленняはПовідомленняキューに蓄えられ、 Повідомленняの受信要求により取り出すが、 Повідомленняハンドラを定義することにより、 指定したタイプのПовідомленняを受信した場合に、 非同期な処理を行なうことが可能である。 これは一種の割り込み処理として使用される。

1.2.3 Повідомленняハンドラ

Повідомленняハンドラとは、 受信したПовідомленняを現在実行中の処理と非同期に処理するための関数であり、 Повідомленняのタイプと、対応する関数を指定することにより定義される。 従って、Повідомленняの各タイプに対応した最大 31 種のПовідомленняハンドラを同時に定義可能である。

Повідомленняハンドラは以下に示す形で起動されて実行される。

  • 対応するタイプのПовідомленняを受信した場合、 Повідомленняハンドラは、メインタスクの現在の処理に割り込む形で実行される。

  • 何らかのシステムコールによる待ち状態の時にПовідомленняが送信された場合にもПовідомленняハンドラは起動され、 そのПроцеси та потокиのメインタスクが実行状態となる。
    この場合、メインタスクが実行中の長い待ちを伴ったシステムコールは無条件に中断され、 その結果は保証されない。 即ち、Повідомленняハンドラが終了した時点で、 中断されたシステムコールは ER_MINTR のエラーとして戻る。

  • Повідомленняハンドラは通常のПроцеси та потокиコードの一部として動作し、 実行できるシステムコール等の制限はない。

  • Повідомленняハンドラが終了した場合は、 通常、割り込まれた位置からそのメインタスクの実行が再開されるが、 Повідомленняハンドラから直接 longjmp () により、 そのメインタスクの任意の位置 ( setjmp で指定された位置 ) に実行を移行することも可能である。

  • Повідомленняハンドラはネスティングしない。 即ち、新たなПовідомленняハンドラの起動 ( 別のПовідомленняタイプのものも含む ) は、 現在処理中のПовідомленняハンドラの終了まで待たされる。

  • Повідомленняハンドラが起動された場合、 その起動の原因となったПовідомленняはПовідомленняキューから取り出され、 取り出されたПовідомленняのポインタがハンドラのパラメータとして渡される。

  • Повідомленняハンドラは、必ず ret_msg () システムコールによって終了しなくてはいけない。

Повідомленняハンドラは、以下に示す形の関数として定義される。 

    VOID msg_hdr(W pid, MESSAGE *r_msg)
    {
    /*  pid は 送信したПроцеси та потокиの ID 。(自Процеси та потокиの場合は 0) */
    /*  r_msg は受信したПовідомленняへのポインタである。 */

        受信Повідомленняの処理

        ret_msg (0);            /* 終了 (割り込んだ位置に戻る場合) */

        または

        ret_msg (1);            /* 終了 (任意の位置に移行する場合) */
        longjmp (reent, code);  /* reent へジャンプする */
    }

特殊なПовідомленняハンドラとして以下のシステム定義のものが存在し、使用することができる。

MH_NONE :

何もせずに、Повідомленняは無視される。 この場合は、例外的に待ちを含むシステムコールは中断されない。 これは、単にある特定のタイプのПовідомленняをキューにも入れずに完全に無視するために使用される。

MH_BREAK :

何もせずに、Повідомленняは無視される。 この場合は、待ちを含むシステムコールは中断され、 ER_MINTR エラーが戻る。 これは、タイムアウト等の処理に使用される。

MH_TERM :

自Процеси та потокиを異常終了し、 MS_ABORT Повідомлення ( エラーコードは 0 ) を親Процеси та потокиに送信する。

1.2.5 システムコール

snd_msg
 
Повідомлення送信

【形式】

ERR snd_msg(W pid, MESSAGE* msg, W opt)

【パラメータ】

W        pid    送信先Процеси та потоки ID
                   > 0   任意のПроцеси та потоки
                   = 0   自Процеси та потоки
                   =-1   親Процеси та потоки
MESSAGE* msg    送信Повідомлення
W        opt    送信待ち属性 ( NOWAIT ‖ WAIT ‖ CONFM )
NOWAIT :

Повідомленняを送信先Процеси та потокиのПовідомленняキューに入れた時点で正常終了する。 送信先のПовідомленняキューに空きがない時はエラー終了する。

WAIT :

Повідомленняを送信先Процеси та потокиのПовідомленняキューに入れた時点で正常終了する。 Повідомленняキューに空きがない時は空きができるまで待つ。 待っている間に送信先Процеси та потокиが終了した場合はエラー終了する。

CONFM :

Повідомленняを送信先Процеси та потокиのПовідомленняキューに入れ、 送信先Процеси та потокиが送信したПовідомленняを受信、 またはПовідомленняキューからクリアした時点で正常終了する。 それまで待つ。

rcv_msg() で CHECK 指定によりヘッダ部分のみを得た場合には、 受信したとみなされない。 NOCLR 指定により受信した場合は、 キューに残っていても受信したとみなされる。 待っている間に送信先Процеси та потокиが終了した場合はエラー終了する。 送信先が自Процеси та потокиの場合、CONFM 指定はエラーとなる。

【リターン値】

＝0    正常
＜0    エラー(エラーコード)

【解説】

pid で指定したПроцеси та потокиにПовідомленняを送信する。

【エラーコード】

ER_ADR      : アドレス(msg)のアクセスは許されていない。
ER_MINTR    : Повідомленняハンドラが起動されたため待ち処理が中断された。
ER_NOPRC    : Процеси та потоки(pid)は存在していない。
              Повідомленняキューの空き待ち、または確認待ちの間に送信先のПроцеси та потокиが終了した。
ER_NOSPC    : システムのメモリ領域が不足した
              (送信先のПовідомленняキューがフル(NOWAIT指定時))。
ER_PAR      : パラメータが不正である(オプション,Повідомленняタイプが不正)。
ER_SELF     : 自Процеси та потокиを指定した(pid = 0 または自Процеси та потокиのPID)(CONFM指定時)。
ER_SZOVR    : Повідомлення本体のサイズがシステムの制限を越えた、または0以下である。
rcv_msg
 
Повідомлення受信

【形式】

WERR    rcv_msg(W t_mask, MESSAGE* msg, W msgsz, W opt)

【パラメータ】

W        t_mask 受信対象Повідомленняタイプマスク
MESSAGE* msg    受信Повідомлення格納領域
W        msgsz  受信Повідомлення格納領域全体のバイトサイズ
                Повідомленняのヘッダ部分も含むため msgsz ≧ 8でなくてはいけない。
W        opt    受信属性 (WAIT ‖ NOWAIT ‖ WAIEVT) | (CLR ‖ NOCLR) | (CHECK)
WAIT :

指定タイプのПовідомленняを受信していない時は、Повідомленняが来るまで待つ。

NOWAIT :

指定タイプのПовідомленняを受信していない時は、エラー終了する。

WAIEVT :

指定タイプのПовідомленняを受信していない時は、 指定タイプのПовідомленняが来るか、イベント発生まで待つ。

CLR :

Повідомленняを受信した後はそのПовідомленняをキューから取り除く。

NOCLR :

Повідомленняを受信した後もそのПовідомленняをキューに残しておく。

CHECK

Повідомленняの有無をチェックする。

【リターン値】

＞0   正常(受信Повідомленняの送信元Процеси та потоки ID)
＝0   正常(受信Повідомленняの送信元は自Процеси та потоки)
＜0   エラー(エラーコード)

【解説】

自Процеси та потоки宛の指定したタイプのПовідомленняを受信する。

受信したПовідомленняが指定した領域に入り切らない場合は、 msgsz の範囲内のみ msg の領域に格納されてエラー終了する。 この時は、CLR 指定があってもПовідомленняはバッファに残る。 ただし、msgsz < 8 の時は msg の領域には何も格納されない。 Повідомленняの全体が格納できなかった場合は、 格納されたПовідомленняのヘッダ部分から実際のПовідомленняサイズが判断できるので、 そのПовідомленняが格納可能な十分な大きさの領域を用意して再度本システムコールを実行することになる。

CHECK 指定の時は、 次のような動作になる。

  1. Повідомленняが何も存在しない場合、WAIT または WAIEVT 指定時は待ち、 NOWAIT 指定時はエラー終了する。

  2. 指定したタイプのПовідомленняが存在している場合は、 msg にПовідомленняを格納し正常終了する。 CLR 指定であればキューから取り除き、 NOCLR 指定であればキューに残す。

  3. 指定したタイプのПовідомленняが存在せず、 それ以外のПовідомленняが存在している場合は、 Повідомленняの先頭 8 バイト ( msg_type と msg_size ) のみを msg に格納し正常終了する。 この場合、CLR 指定があってもПовідомленняはキューに残す。

CHECK 指定の時は、 指定したタイプ以外のПовідомленняが得られる可能性があるため、 受信したПовідомленняのタイプを必ずチェックする必要がある。

WAIEVT を指定は基本的な動作は WAIT 指定と同じであるが、 Повідомленняが受信されていなくても、 brk_msg() によりイベント発生が通知されると待ちが解除される。 この場合、エラー ( ER_NOME ) 終了する。

WAIEVT を指定した場合は、 t_mask = 0 が指定できる。 この場合、Повідомленняの受信は行われず、イベント発生が通知されるまで待つ。

WAIEVT を指定できるのは同時にはシステム全体で 1 つのタスクのみで、 複数のタスクが WAIEVT 指定で rcv_msg() を呼び出したときは、 最後に呼び出したタスクの WAIEVT 指定のみが有効となる。 他のタスクは WAIT と同じ扱いとなる。

WAIEVT は外殻 ( ウインドウマネージャ ) の wget_evt() の実現のために用意されたオプションである。 アプリケーションは WAIEVT を指定してはいけない。

【エラーコード】

ER_ADR      : アドレス(msg)のアクセスは許されていない。
ER_MINTR    : Повідомленняハンドラが起動されたため待ち処理が中断された。
ER_NONE     : 指定したタイプ(t_mask)のПовідомленняは存在しない(NOWAIT指定時)。
ER_PAR      : パラメータが不正である
              (msgsz が小さすぎる、
               WAIEVT指定時以外 t_mask≦0、WAIEVT指定時 t_mask<0)。
clr_msg
 
Повідомленняクリア

【形式】

ERR clr_msg(W t_mask, W last_mask)

【パラメータ】

W   t_mask      クリア対象Повідомленняタイプマスク
                = MM_ALL     全Повідомленняタイプ

W   last_mask   クリア終了Повідомленняタイプマスク
                = MM_NULL    対象はПовідомленняキューの最後まで
                = MM_ALL     Повідомленняを1つだけクリア

【リターン値】

＝0    正常
＜0    エラー(エラーコード)

【解説】

自Процеси та потоки宛の指定したタイプの受信済みПовідомленняをクリアする。

自Процеси та потокиのПовідомленняキューに受信済みのПовідомленняのうち、 t_mask で指定したタイプのПовідомленняを last_mask で指定したタイプのПовідомленняの直前までクリアする。 last_mask で指定したタイプのПовідомленняはクリアされないが、 last_mask = MM_ALL の時は、 特別にПовідомленняを 1 つだけクリアすることを意味する。

t_mask と last_mask の指定例を以下に示す。

t_masklast_mask動作
MM_ALLMM_NULL 受信済みの全Повідомленняをクリア
− MM_ALL t_mask で指定したПовідомленняを 1 つだけクリア
MM_ALLMM_ALL 先頭のПовідомленняを1つだけクリア

【エラーコード】

ER_PAR  : パラメータが不正である(t_mask≦0、last_mask<0)。
req_tmg
 
タイムアウトПовідомлення要求

【形式】

ERR req_tmg(W time, W code)

【パラメータ】

W   time    Повідомлення送信時間(ミリ秒)
W   code    タイムアウトПовідомленняのコード

【リターン値】

＝0    正常
＜0    エラー(エラーコード)

【解説】

自Процеси та потоки宛に指定した時間後にタイムアウトПовідомлення ( MS_TMOUT ) を送信することを要求する。

この機能は、 Повідомленняハンドラと組み合わせて特定の処理のタイムアウト監視などに使用される。

【エラーコード】

ER_NOSPC    : システムのメモリ領域が不足した。
ER_PAR      : パラメータが不正である(time≦0)。

     ERR can_tmg()

def_msg
 
Повідомленняハンドラ定義

【形式】

  ERR def_msg(W t_mask, FP msghdr)

【パラメータ】

W   t_mask  対象Повідомленняタイプマスク

FP  msghdr  Повідомленняハンドラ開始アドレス
            = NULL      Повідомленняハンドラの定義解除
            = MH_NONE   システム定義ハンドラ(無視)
            = MH_BREAK  システム定義ハンドラ(処理中断)
            = MH_TERM   システム定義ハンドラ(Процеси та потоки終了)

【リターン値】

＝0    正常
＜0    エラー(エラーコード)

【解説】

指定したタイプのПовідомленняに対応するПовідомленняハンドラを定義する。

同じタイプのПовідомленняに対するПовідомленняハンドラがすでに定義されている場合には、 後から定義したПовідомленняハンドラが有効となる。

【エラーコード】

ret_msg
 
Повідомленняハンドラ終了

【形式】

ERR ret_msg(W ret)

【パラメータ】

W   ret リターン指定
＝0 :
Повідомленняハンドラが割り込んだ位置から実行を再開し、 本システムコールからは戻らない。
待ちを含むシステムコールの実行中に割り込んだ場合、 そのシステムコールの実行は保証されずに、 Повідомленняハンドラが起動されたことを示すエラーコードがそのシステムコールから戻る。
≠0 :
Повідомленняハンドラが割り込んだ位置からは再開せずに、 本システムコールから戻って、 そのまま実行を続行する。 この場合、通常はハンドラの最後で longjmp () により制御を他へ移行することになる。

【リターン値】

リターンしない(ret = 0 の時)
＝0     正常(ret≠ 0 の時)

【解説】

Повідомленняハンドラの実行を終了する。

Повідомленняハンドラの最後には必ず本システムコールを実行しなくてはいけない。 また、本システムコールはПовідомленняハンドラ内でのみ発行することができ、 それ以外の部分で発行された時はシステムエラーとなる。

Повідомленняハンドラの起動要求が多重に発生していた場合、 本システムコールの実行後に要求のあったПовідомленняハンドラが起動する。

【エラーコード】

発生しない。
