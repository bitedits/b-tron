Розділ 3. Детальна специфікація формату документів TAD

3.1 Вступ

Ця специфікація описує детальні структури даних стандарту TAD (TRON Application Databox), який є уніфікованим форматом збереження та обміну гіпертекстовими, графічними, растровими документами й ієрархічними мережами об'єктів у середовищі BTRON3.

3.2 Структура Реального об'єкта TAD (Real Object Layout)

3.2.1 Загальні відомості

Кожен Реальний об'єкт (файл даних TAD) зберігається на носії у вигляді послідовності записів (Records). Записи можуть містити текстові потоки, геометричну графіку, вкладені віртуальні об'єкти (посилання), а також допоміжні ресурси.

3.2.2 Структура записів Реального об'єкта

typedef struct {
    UH  rec_type;   /* Тип запису TAD (TR_TEXT, TR_FIG, TR_VOBJ тощо) */
    UW  len;        /* Довжина даних запису у байтах */
} TAD_RECORD_HDR;

#define TR_TEXT     0x0001  /* Текстовий запис */
#define TR_FIG      0x0002  /* Графічний запис (векторна графіка) */
#define TR_VOBJ     0x0003  /* Запис Віртуального об'єкта (посилання / Link) */
#define TR_CONT     0x4000  /* Прапор продовження розділеного запису */

3.3 Огляд структури даних TAD

3.3.1 Формат сегментів TAD

Дані всередині запису складаються з послідовності сегментів змінної довжини: 

typedef struct {
    UB  id;         /* Ідентифікатор сегмента (Segment ID) */
    UB  len;        /* Довжина сегмента у байтах (без урахування заголовка) */
} TAD_SEG_HDR;

3.3.2 Текстові та графічні дані

Текст представлена послідовністю символів TRON Code (2 байти на символ) з можливістю вкраплення функціональних вкладок (Fusen). Графіка описується векторними сегментами фігур, ліній, патернів заливки та кольорів.

3.3.3 Растрові зображення (Image Data)

Растрові елементи (бітові карти) зберігаються у вигляді сегментів TS_IMAGE, що підтримують палітри кольорів, глибину від 1 до 32 біт на піксель та алгоритми стиснення.

3.3.4 Опис структур даних TAD мовою C

typedef struct {
    TAD_SEG_HDR hdr;
    B           data[1];    /* Масив даних сегмента */
} TAD_SEG;

3.4 Детальний опис базових сегментів TAD

3.4.1 Огляд базових сегментів

3.4.2 Сегмент службової інформації керування (TS_HEADER / TS_SYSTEM)

#define TS_HEADER   0x00    /* Заголовок управління документом */
#define TS_SYSTEM   0x01    /* Системна інформація додатків */

3.4.3 Сегменти початку та завершення тексту

#define TS_TBGN     0x02    /* Початок текстового блоку */
#define TS_TEND     0x03    /* Завершення текстового блоку */

3.4.4 Сегменти початку та завершення графіки

#define TS_GBGN     0x04    /* Початок графічного блоку */
#define TS_GEND     0x05    /* Завершення графічного блоку */

3.4.5 Сегмент растрового зображення (TS_IMAGE)

#define TS_IMAGE    0x06    /* Растрове зображення */

typedef struct {
    TAD_SEG_HDR hdr;        /* id = TS_IMAGE */
    H           width;      /* Ширина растру у пікселях */
    H           height;     /* Висота растру у пікселях */
    H           rowbytes;   /* Кількість байтів у рядку растру */
    UH          pixbits;    /* Глибина кольору (1, 2, 4, 8, 16, 24, 32 біти) */
    UH          compress;   /* Алгоритм стиснення (0 = без стиснення, 1 = RLE) */
} IMAGE_SEG_HDR;

3.4.6 Сегмент Віртуального об'єкта (TS_VOBJ / Link)

Сегмент TS_VOBJ вставляє візуальне посилання (іконку чи рамку) на інший Реальний об'єкт: 

#define TS_VOBJ     0x07    /* Посилання на віртуальний об'єкт */

typedef struct {
    LINK        vlnk;       /* Ідентифікатор файлової системи та ID цільового файлу */
    RECT        frame;      /* Розміри та рамка відображення іконки на екрані */
    TC          name[12];   /* Назва Віртуального об'єкта */
} VOBJSEG;

3.4.7 Сегменти функціональних вкладок (TS_FUSEN / Фусени)

Функціональна вкладка (Fusen) — це розширюваний блок керування макетом, форматуванням або параметрами документа, що вбудовується безпосередньо у потік даних TAD.
