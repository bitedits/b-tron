1.2 Система міжпроцесних повідомлень (Message Passing)

1.2.1 Огляд міжпроцесних повідомлень (Overview)

Кожен процес має власну чергу повідомлень (Message Queue), через яку здійснюється міжпроцесний обмін повідомленнями. Ця функціональність використовується не лише для передачі повідомлень прикладних програм між процесами, а й для системних сповіщень ядра (наприклад, повідомлень про завершення дочірніх процесів). З цієї причини формати окремих типів повідомлень регламентуються системою.

Повідомлення надсилається у чергу повідомлень цільового процесу, а адресат вказується за допомогою його ідентифікатора процесу PID. Також процес-відправник однозначно ідентифікується за власним PID.

Кожне повідомлення має наведену нижче структуру і поділяється на 31 тип за полемmsg_type(1 – 31). Завдяки побітовій масці типів (Type Mask) під час прийому або очищення повідомлень можна вибірково вказувати один або кілька типів повідомлень одночасно. 

typedef union {
 struct {
 W pid;
 W code;
 } ABORT; /* Повідомлення про аварійне завершення процесу (MS_ABORT) */
 struct {
 W pid;
 W code;
 } EXIT; /* Повідомлення про нормальне завершення процесу (MS_EXIT) */
 struct {
 W pid;
 W code;
 } TERM; /* Повідомлення про примусове завершення процесу (MS_TERM) */
 struct {
 W code;
 } TMOUT; /* Повідомлення про спливання таймауту (MS_TIMEOUT) */
 struct {
 W code;
 } SYSEVT; /* Повідомлення про системні події (MS_SYS1..MS_SYS31) */
 struct {
 UB msg_str[32];
 } ANYMSG; /* Загальні повідомлення додатків (MS_USER) */
} MSGBODY;

typedef struct message {
 W msg_type; /* і надсилає батьківському процесу системне повідомлення MS_ABORT з кодом 0. */
 W msg_size; /* Розмір тіла повідомлення (байти) */
 MSGBODY msg_body; /* Буфер тіла повідомлення */
} MESSAGE;

У чергу повідомлень процесу можуть надходити як повідомлення від інших процесів, так і повідомлення від власного процесу (якщо цільовим адресатом вказано власний процес), і надсилає батьківському процесу системне повідомлення MS_ABORT з кодом 0.Повідомлення про спливання таймауту (MS_TIMEOUT)。 Крім того, повідомлення про завершення дочірніх процесів також надходять у цю чергу.

Черга повідомлень працює за принципом FIFO — повідомлення записуються суворо у порядку надсилання. Якщо під час відправлення черга отримувача заповнена, відправник може заблокуватися до появи вільного місця або негайно повернути код помилки.

Зазвичай прийняті повідомлення накопичуються у черзі і вилучаються за запитом прийому повідомлення, проте за допомогою реєстрації обробника повідомлень (Message Handler) при надходженні повідомлення вказаного типу можна виконувати асинхронну обробку. Це застосовується як системне переривання.

Система надає 3 готові системні обробники за замовчуванням:

MH_NONE:

Повідомлення ігнорується без виконання дій. У цьому випадку заблоковані системні виклики очікування НЕ перериваються. Застосовується для повного ігнорування повідомлень певного типу.

MH_BREAK:

Повідомлення ігнорується без виконання дій. Повідомлення ігнорується, але заблоковані виклики очікування перериваються ER_MINTRі повертають код помилки ER_MINTR. 、Спливання таймауту。
