3.1 Віконна система (Windowing System)マネージャ

3.1.1 Віконна система (Windowing System)マネージャの機能

3.1.1.1 概要

Віконна система (Windowing System)マネージャは外殻の HMI 機能の中心的な機能であり、 画面表示上の操作環境の基本となる空間であるСистемні панелі (Panels)プレーン上に存在する複数のオーバラップしうるСистемні панелі (Panels)の生成 / 削除 / 表示 / 操作等に関する基本的な機能を提供している。

Віконна система (Windowing System)マネージャでは、 基本的にСистемні панелі (Panels)プレーン上のフローティングСистемні панелі (Panels) ( ウインドウ ) の管理のみを行ない、 ダイアローグタイプのСистемні панелі (Panels)やシステムСистемні панелі (Panels)は独立したСистемні панелі (Panels)マネージャにより管理されることになる。

Віконна система (Windowing System)には必ず対応するアプリケーションПроцеси та потокиが存在し、 そのアプリケーションПроцеси та потокиがВіконна система (Windowing System)マネージャで提供している機能を一定のルールに従って使用することにより、 実際のВіконна система (Windowing System)の表示 / 操作が行なわれ、 全体としてのВіконна система (Windowing System)システムが実現されることになる。 従って、Віконна система (Windowing System)を使用するすべてのアプリケーションは、 アプリケーションテンプレートとして規定されたプログラム構造を持たなくてはいけない。

Віконна система (Windowing System)マネージャは、タイトル、 スクロールバーを含んだВіконна система (Windowing System)枠部分のみの表示を行ない、 Віконна система (Windowing System)内部の表示は、 対応するアプリケーションПроцеси та потокиが自分で行なうことになる。 このための描画環境はВіконна система (Windowing System)マネージャにより用意される。

Віконна система (Windowing System)システムの実現方法には幾つかの方式があるが、 ここでは基本的に特殊ハードウェアサポートが無いことを前提としており、 またВіконна система (Windowing System)が重なって隠れた部分の表示イメージは、 原則的に保存されないことを前提としている。

これにより、最小限のハードウェアと、 メモリによるВіконна система (Windowing System)システムの実現を可能としているが、 実際のインプリメントにおいて、 特殊なハードウェアを使用したり、 隠れたイメージを自動的に保存 / 再現することを禁止しているわけではない。

なお、Віконна система (Windowing System)マネージャが管理する表示画面は、 最下部のシステムПовідомленняСистемні панелі (Panels)を除いた部分となる。 ただし、フルスクリーンモードの場合は、 システムПовідомленняСистемні панелі (Panels)を含めたスクリーン全部に、Віконна система (Windowing System)が表示される。

3.1.1.2 Віконна система (Windowing System)

Віконна система (Windowing System)のタイプ

Віконна система (Windowing System)はユーザがアプリーケションを操作する上での環境としての、 画面上の 1 つの独立した矩形領域である。 この矩形領域は基本的に自由に移動 / 変形が可能であり、 前後関係を持って互いにオーバーラップされて表示される。

Віконна система (Windowing System)には、以下に示す 4 種類があり、 単にВіконна система (Windowing System)と言った場合は、 通常Віконна система (Windowing System)を意味する。

通常Віконна система (Windowing System)

一般のアプリケーションが使用する通常のВіконна система (Windowing System)。

前面Віконна система (Windowing System)

フロントエンド機能を提供する特殊なアプリケーションが使用するВіконна система (Windowing System)であり、常に最前面に置かれる。

Системні панелі (Panels)Віконна система (Windowing System)

ダイアローグタイプのСистемні панелі (Panels)として使用される特殊なВіконна система (Windowing System)で通常Віконна система (Windowing System)の上で前面Віконна система (Windowing System)の下に表示される。 このタイプのВіконна система (Windowing System)はСистемні панелі (Panels)マネージャによって使用され、 一般のアプリケーションが直接使用することはない。 また、適用可能な操作も非常に限定される。

内部Віконна система (Windowing System)

独立した描画環境をВіконна система (Windowing System)として取り扱うために内部的に使用される特殊な擬似的なВіконна система (Windowing System)である。 このタイプのВіконна система (Windowing System)は、 実身 / 仮身マネージャにより使用され、 一般のアプリケーションが直接使用することはない。 また、適用可能な操作も非常に限定される。

通常Віконна система (Windowing System)は、さらに以下の 2 種類に分類される。

主Віконна система (Windowing System)

アプリケーションの表示 / 操作の中心となるВіконна система (Windowing System)。

従属Віконна система (Windowing System)

主Віконна система (Windowing System)の表示/操作の補助のために使用されるВіконна система (Windowing System)であり、 論理的に主Віконна система (Windowing System)と同一のВіконна система (Windowing System)として取り扱われる。 従属Віконна система (Windowing System)は常に主Віконна система (Windowing System)の前面に表示される。

なお、前面Віконна система (Windowing System)は、 存在する全ての主Віконна система (Windowing System)に共有される従属Віконна система (Windowing System)として取り扱われ、 現在入力受付状態のВіконна система (Windowing System)を主Віконна система (Windowing System)とした場合の従属Віконна система (Windowing System)と同様に取り扱われる。

入力受付状態

ある時点で、 ユーザからのインタラクティブな操作が可能なВіконна система (Windowing System)を入力受付状態のВіконна система (Windowing System)と呼び、入力受付状態でないВіконна система (Windowing System)を入力不可状態のВіконна система (Windowing System)と呼ぶ。

入力受付状態は主Віконна система (Windowing System)間で任意に切り換えることができ、 ある時点で 1 つの主Віконна система (Windowing System)のみが入力受付状態となりうる。 主Віконна система (Windowing System)を新たにオープンした時点では、 その主Віконна система (Windowing System)に入力受付状態が切り換わる。

主Віконна система (Windowing System)が入力受付状態の場合は、 それに従属するすべての従属Віконна система (Windowing System)も入力受付状態となる。 主Віконна система (Windowing System)が入力不可状態の場合は、 それに従属するすべての従属Віконна система (Windowing System)の表示は消去され見えない状態となる。 この状態を不可視状態と呼ぶ。 従って、従属Віконна система (Windowing System)は、 対応する主Віконна система (Windowing System)が入力受付状態の場合のみ表示されて「見える」存在となる。

前面Віконна система (Windowing System)は、 ユーザからインタラクティブな操作に対してフロントエンドとしての一種の前処理を行なうため、 その意味で常に入力受付状態を主Віконна система (Windowing System)と共有していると言える。 即ち、 ユーザーからインタラクティブな操作は、 常に前面Віконна система (Windowing System)を経由して、 入力受付状態の主Віконна система (Windowing System)に送られることになる。

Системні панелі (Panels)Віконна система (Windowing System)は、ダイアローグタイプのСистемні панелі (Panels)として使用され、 Системні панелі (Panels)Віконна система (Windowing System)がオープンされている間は、 入力受付状態を主Віконна система (Windowing System)から横取りして占有することになる。 Системні панелі (Panels)Віконна система (Windowing System)がクローズされた時点で、 入力受付状態は元の主Віконна система (Windowing System)に戻される。 複数のСистемні панелі (Panels)Віконна система (Windowing System)がオープンされた場合は、 最後にオープンされたСистемні панелі (Panels)Віконна система (Windowing System)が入力受付状態を占有し、 Системні панелі (Panels)Віконна система (Windowing System)のクローズにより順番に元のВіконна система (Windowing System)に入力受付状態が戻ることになる。

内部Віконна система (Windowing System)に対しては、入力受付状態は定義されない。

Віконна система (Windowing System)の親子関係

通常、 主Віконна система (Windowing System)は仮身に対してアプリケーションを実行することにより生成されることが多い。 この場合、 元となった仮身が存在していた主Віконна система (Windowing System)を生成された主Віконна система (Windowing System)の親Віконна система (Windowing System)と呼ぶ。

従って、 主Віконна система (Windowing System)全体はその親子関係により木構造となっていることになる。 主Віконна система (Windowing System)の親子関係は画面上の表示には一切反映されないが、 主Віконна система (Windowing System)を閉じた場合は、 その元となった仮身に戻ることになり、 その結果、 親Віконна система (Windowing System)に入力受付状態が切換わることになる。

主Віконна система (Windowing System)の親Віконна система (Windowing System)は、 Віконна система (Windowing System)のオープン時に指定されるが、 オープン後も変更することが可能である。 また、Віконна система (Windowing System)が閉じられた場合、 そのすべての子Віконна система (Windowing System)の親Віконна система (Windowing System)は閉じたВіконна система (Windowing System)の親Віконна система (Windowing System)に自動的に変更される。

主Віконна система (Windowing System)以外のВіконна система (Windowing System)に対しては、親Віконна система (Windowing System)は定義されない。

親を持つВіконна система (Windowing System)にはその生成の元となった仮身の表示上の領域が定義され、 この領域を生成元と呼ぶ。生成元は、親Віконна система (Windowing System)内の相対座標により定義される。

生成元も、Віконна система (Windowing System)のオープン時に指定されるが、 オープン後も変更することが可能である。 また、Віконна система (Windowing System)が閉じられた場合、 そのすべての子Віконна система (Windowing System)の生成元は閉じたВіконна система (Windowing System)の生成元と同じものに自動的に変更される。

なお、仮身の移動等に伴う、 親Віконна система (Windowing System)および生成元の変更は、実身 / 仮身マネージャにより行なわれる。

Віконна система (Windowing System)のモード

主Віконна система (Windowing System)には、 全面モードと通常モードが定義され、 交互に切り換えが可能となる。

全面モードでは、 主Віконна система (Windowing System)は画面一杯に拡がって表示され、 通常モードに戻すことにより、元の位置、大きさの表示に戻る。

全面モードで表示されている状態で、 Віконна система (Windowing System)の移動 / 変形を行なった場合は、 そのВіконна система (Windowing System)の全面モード状態は解除され、 通常モードの表示と見なされることになる。

主Віконна система (Windowing System)以外のВіконна система (Windowing System)に対しては、このモードは定義されない。

3.1.1.3 Віконна система (Windowing System)の表示

ここでは、通常Віконна система (Windowing System)、 および前面Віконна система (Windowing System)の標準的な表示形状に関して説明しているが、 表示形状の詳細はインプリメントに依存する。 内部Віконна система (Windowing System)、Системні панелі (Panels)Віконна система (Windowing System)に関しては、 Віконна система (Windowing System)マネージャでは表示を行なわないため表示形状は定義されない。

○ EV_SWITCH

    cmd :  位置コード (W_WORK (0)〜W_LBAR (10))
           W_SWITCH (128)
           W_CLOSED (129)

位置コードの場合は、 PD のプレスにより入力受付状態の切換えが発生したことを意味し、 プレスした位置の位置コード、 および相対座標位置が入っている。 アプリケーションはこのイベントを EV_BUTDWN として処理する必要がある。

W_SWITCH の場合は、 アプリケーションからの要求による入力受付状態の切り換え、 または、 Системні панелі (Panels)のクローズによる入力受付状態の切り換えが発生したことを意味し、 PD の位置に関する情報は存在しない。

    src :  0     Віконна система (Windowing System)の切り換え
           1     Системні панелі (Panels)のクローズ

W_CLOSED の場合は、 子Віконна система (Windowing System)がクローズされたため親Віконна система (Windowing System)に入力受付状態が切換わったことを意味し、 この時点では、 既に子Віконна система (Windowing System)はクロージングアニメーションとともに削除されている。 src には、クローズした子Віконна система (Windowing System)のВіконна система (Windowing System)IDが入り、 r には、生成元の矩形領域が相対座標で入っている。

○ EV_REQUEST

Віконна система (Windowing System)マネージャ、 または他のПроцеси та потокиからの各種の処理の要求およびそれに対する応答を示すイベントであり、 対象とするВіконна система (Windowing System)の管理Процеси та потокиが得るものであり、 アクティブПроцеси та потокиと非アクティブПроцеси та потокиの両方から取り出される。 

    cmd は要求する処理内容を示す以下のものである。
    cmd :  W_REDISP (0)  -- Віконна система (Windowing System)の再表示要求
           W_PASTE  (1)  -- データの貼り込み要求
           W_DELETE (2)  -- Віконна система (Windowing System)のクローズ要求
           W_FINISH (3)  -- 処理の終了要求
           W_VOBJREQ(4)  -- 仮身の再表示要求
           W_OPENED (5)  -- Віконна система (Windowing System)のオープン通知
               :   :

           W_ACK (0x40)+(要求コード) -- 要求に対するACK応答
           W_NAK (0x80)+(要求コード) -- 要求に対するNACK応答

W_REDISP は、 Віконна система (Windowing System)の再表示を要求するもので、 Віконна система (Windowing System)の操作に伴って、 Віконна система (Windowing System)の再表示が必要になった場合にВіконна система (Windowing System)マネージャが発生するイベントである。 このイベントを得た場合は、 アプリケーションは対応するВіконна система (Windowing System)の再表示を速やかに行なわなくてはならない。 

        src =0 : 通常再表示要求
            =1 : Системні панелі (Panels)再表示要求

W_REDISP 以外のものは、 Віконна система (Windowing System)マネージャとしては特別な処理を行なわず、 要求イベントの送付、 および応答イベントの送付を行なう。 要求イベントの src にはВіконна система (Windowing System)マネージャにより要求したПроцеси та потоки ID が設定され、 応答イベントの宛先として使用される。

各要求イベントは、以下の意味を持つ。

W_PASTE:

ドラッグによるデータの移動 / 複写のために使用され、 移動 / 複写先のВіконна система (Windowing System)に対して移動 / 複写元のПроцеси та потокиがこのイベントを送信する。
このイベントを受信したПроцеси та потокиは速やかに要求された貼り込み処理を行ない、 必ず、W_ACK または W_NAK の応答を戻さなくてはいけない。

W_DELETE:

Віконна система (Windowing System)のクローズ要求のために使用される。 このイベントを受信したПроцеси та потокиは速やかにВіконна система (Windowing System)のクローズ処理を行ない、必ず W_ACK ( または W_NAK ) の応答を戻さなくてはいけない。

W_FINISH:

処理の終了要求のために使用される。 このイベントを受信したПроцеси та потокиは即座に処理を終了し、 必ず W_ACK ( または W_NAK ) の応答を戻さなくてはいけない。

W_VOBJREQ:

仮身に対する各種の操作 / 表示要求を行なうために使用され、 実身 / 仮身マネージャが送信する。 このイベントを受信したПроцеси та потокиは、 速やかに要求された処理を行なわなくてはいけない。 応答は不要である。詳細は、 「3.8 実身／仮身マネージャ」 を参照のこと。

W_OPENED:

子Процеси та потокиが親Процеси та потокиに対して、 新たにオープンしたВіконна система (Windowing System) ID を通知するために使用する。 一般に応答は不要である。

Меню та командні інтерфейсиボタンがプレスされた場合、 もしくは PD のプレス時に命令キーがプレスされていた場合に得られるイベントであり、 Меню та командні інтерфейсиの表示を行なうことを意味する。 PD 位置は絶対座標であるが、 対応するВіконна система (Windowing System) ID および位置コードが設定されている。

Віконна система (Windowing System)イベントの処理

Віконна система (Windowing System)Обробка подійは、 要求したПроцеси та потокиがアクティブПроцеси та потокиか否かで大きくその内部処理が異なる。

アクティブПроцеси та потокиの場合は、核イベントを取り出し、 対応するВіконна система (Windowing System)のサーチ、相対座標への変換、Меню та командні інтерфейси指定のチェック、 ポインタ形状の変更、入力受付状態の切り換え等の処理を行なったのち、 必要に応じて後述するフロントエンド処理を行ない、 Віконна система (Windowing System)イベントとして戻す。

非アクティブПроцеси та потокиの場合は、Повідомленняを取り出し、 内部イベントПовідомленняとして得られた EV_SWITCH、 EV_REQUEST をВіконна система (Windowing System)イベントとして戻す。 この場合、他のПовідомленняも受信するため、 内部イベントПовідомлення以外のПовідомленняを受信した場合は、 その旨を戻すことになる。 またПовідомлення受信を待つか否かの指定を行なうことが可能で、 待たない指定を行なった場合でПовідомленняが何も無かった場合は、 その旨を戻す ( EV_NOMSG )。

入力受付状態でない ( 即ち非アクティブПроцеси та потоки ) 状態で、 Віконна система (Windowing System)の表示を更新する場合は、待たない指定を行なう必要がある。

内部イベントПовідомленняは入力受付状態の切り換え、 Віконна система (Windowing System)の再表示要求、フロントエンド処理等の際に、 Віконна система (Windowing System)イベントをВіконна система (Windowing System)の管理Процеси та потоки間で受け渡すために使用されるПовідомленняであり、 その詳細はВіконна система (Windowing System)マネージャのインプリメントに依存する。

フロントエンド機能

フロントエンド機能は、 アクティブПроцеси та потокиが取り出す、 Віконна система (Windowing System)イベントを横取りして、 イベントの前処理等を行なう機能であり、 「キーボード表小物」等の特殊なアプリケーションにより使用される。 フロントエンド機能を使用する特殊なПроцеси та потокиをフロントエンドПроцеси та потокиと呼ぶ。

フロントエンドПроцеси та потокиは、 画面表示を必要とする場合、 前面Віконна система (Windowing System)を使用することができ、 各種のВіконна система (Windowing System)操作関数を特別な制限なしで使用することができる。 逆に前面Віконна система (Windowing System)以外のВіконна система (Windowing System)を使用することはできない。

図 58 : フロントエンド機能の基本構造

フロントエンドПроцеси та потокиは wdef_fep(1) により定義され、 同時に最大 4 個まで定義できる。 フロントエンドПроцеси та потокиは、 すべての処理を終了した時点で wdef_fep(0) により、 フロントエンドПроцеси та потокиでなくなるが、 そのПроцеси та потокиが終了した場合は自動的にフロントエンドПроцеси та потокиとしての定義から外される。

フロントエンドПроцеси та потокиが定義されている状態では、 フロントエンドПроцеси та потокиが実質的なアクティブПроцеси та потокиとして取り扱われ、 元のアクティブПроцеси та потокиは擬似アクティブПроцеси та потокиとなり、 非アクティブПроцеси та потокиと同様にПовідомлення待ち状態となる。 なお、 フロントエンドПроцеси та потокиの存在はВіконна система (Windowing System)の表示には一切影響しない。

複数のフロントエンドПроцеси та потокиが定義されている場合は、 最後に定義されたフロントエンドПроцеси та потокиが実質的なアクティブПроцеси та потокиとして取り扱われ、 他はすべて擬似アクティブПроцеси та потокиとなり、 Повідомлення待ち状態となる。

図 60 : フロントエンドПроцеси та потокиへのイベント流れ(2)

フロントエンドПроцеси та потокиの標準的な動作は以下に示すものとなる。

  1. wdef_fep(1) によりフロントエンドПроцеси та потокиとなる。

  2. 通常のПроцеси та потокиと同様に、wget_evt (*evt, WAIT) により、 イベントを取り出して、 その処理を行なうイベントループの構造となる。 wpas_evt() によりイベントを戻す点のみが通常のПроцеси та потокиと異なることになる。

  3. 得られたイベントの処理は、基本的に以下の 3 種類のいずれかとなる。

    1. そのまま何もせずに wpas_evt() で戻す

      自分の前面Віконна система (Windowing System)以外に対する EV_REQUEST、 自分の前面Віконна система (Windowing System)以外での EV_BUTDWN 等

    2. 対応する処理を行なった後、得られたイベントをそのまま、 または変換して wpas_evt() で戻す

      EV_NULL
      ポインタ形状の変更、 ブリンク / ちらつき処理等を行なった後、 そのまま EV_NULL を戻す。

      キーボード小物の場合の例 :

      EV_KEYDWN
      対応するキー表示を反転し、 必要ならキーコードを変換して戻す。
      EV_BUTDWN
      表示されているキー上の場合、 PD をトラックし、 リリース時点のキー表示に対応する EV_KEYDWN を生成して戻す。

    3. 対応する処理を行ない、イベントを戻さない( (空)イベントを戻す)

      自分の前面Віконна система (Windowing System)に対する再表示要求等の EV_REQUEST、 自分の前面Віконна система (Windowing System)に対する PD プレスで、移動、変形操作 等

  5. 処理を終了する場合は、wdef_fep(0) により、 フロントエンドПроцеси та потокиであることをやめる。

フロントエンドПроцеси та потокиには、wdef_fep(1) で定義される一般フロントエンドПроцеси та потокиと、 wdef_fep(-1) で定義される特殊フロントエンドПроцеси та потокиの2つがある。

これによりドラッグ影の描画中に元のВіконна система (Windowing System)の内容をスクロールしたり、 座標系を変更した場合にも、正しいドラッグ影の描画が保証されることになる。 ただし、サイズ変更、移動、および、全面モードの切り換えに関してはトラックされない。

＜ 0  エラー(エラーコード)

【解説】

itemで示されるВіконна система (Windowing System)情報レコードを、buf で示される領域に取り出し、 レコード全体のバイトサイズを返す。 buf から size バイトがアクセスできる必要がある。 buf が NULL の場合や size ≦ 0 の場合はレコードの内容は取り出されないが、 レコードの全体サイズを得ることができる ( エラーにはならない )。

領域が不足した場合 ( 関数値 > size の場合 ) は size バイトまでが格納されるが、 この場合はレコードの種類 ( ポインタを含んでいる構造体など ) によっては取り出される内容は保証されない。

【エラーコード】

EX_ADR      : アドレス(buf)のアクセスは許されていない。
EX_PAR      : パラメータが不正である(itemが不正)。
EX_NOSPT    : itemのВіконна система (Windowing System)情報レコードはサポートされていない。
EX_NOSPC    : システムのメモリが不足した。
wget_inf
 
Віконна система (Windowing System)情報レコードの取り出し

【形式】

ERR wset_inf(W item, VP buf, W size)

【パラメータ】

W   item    Віконна система (Windowing System)情報レコード番号
VP  buf     格納領域へのポインタ
W   size    格納領域のバイトサイズ

【リターン値】

≧ 0  正常(実際に書き込まれたバイトサイズ)
＜ 0  エラー(エラーコード)

【解説】

item で示されるВіконна система (Windowing System)情報レコードを、 buf で示される内容で更新し、 実際に格納されたバイトサイズを返す。 buf から size バイトがアクセスできる必要がある。 buf が NULL の場合や size ≦ 0 の場合は、 レコードの内容をシステムのディフォールト値に戻す。

buf で示される内容が不正な場合には、 EX_PAR のエラーが返る。

【エラーコード】

EX_ADR      : アドレス(buf)のアクセスは許されていない。
EX_PAR      : パラメータが不正である(item, bufが不正)。
EX_NOSPT    : itemのВіконна система (Windowing System)情報レコードはサポートされていない。
              または、bufで示されるデータ形式はサポートされていない。
EX_NOSPC    : システムのメモリが不足した。
