"The first time you turn on a machine should feel like a ceremony, not a gamble — Bootloader makes every boot a deliberate, beautiful act."

Overview

Cleanroom multi-architecture boot manager combining Haiku's aesthetic grace and NetBSD's boot infrastructure reliability. Supports Raspberry Pi 1–5 (ARM MMIO), x86_64 UEFI SMP (ACPI MADT), and NEC PC-9801/PC-9821 VM (Awe Morris kernel) with live command-line editing and multi-core affinity allocation.

スキー・ブートローダー（Bootloader）： B-Systemの公式ブートマネージャ。Haiku流の洗練されたUI造形美とNetBSD水準の堅牢なブートマネージャ品質を融合。Raspberry Pi 1〜5（ARM MMIO）、x86_64 UEFI SMP（ACPI MADT AP起動）、そしてNEC PC-98（i386/i486/Pentium リアルモード）の3大ハードウェアアーキテクチャを統合サポートします。

Key Features

  • Direct Multiboot Single-Stage Loading (core_boot.c) — Eliminates fragile legacy 2-stage MBR/VBR chainloaders; incorporates Multiboot 1 header (0x1BADB002) loaded at 1 MB directly into protected/long mode by QEMU and modern hypervisors
  • Live Hardware Query Pipeline (Zero Mocks) — Subsystems self-report true physical attributes via btron/core.h hooks: CPU MSRs (IA32_APIC_BASE 0x1B), CPUID feature leaves, IO-APIC MMIO redirection depth, HPET femtosecond period counters, and PC-98 I/O ports (0xF2 A20, 0x21/0xA1 PIC IMR)
  • Polymorphic Kernel Core Delegation — core_boot.c acts as a pure sequence orchestrator (btron_core_banner(), btron_core_init(), btron_core_mem_log(), btron_core_hfds_log(), vesa_probe_log()), delegating hardware queries cleanly to machine-specific drivers
  • Ski Interactive Boot Menu — Dual mode: Graphical BTRON glyph canvas and ANSI terminal with keyboard navigation ([↑/↓], [W/S]), inline command line editing ([E]), and multi-core CPU affinity control ([+]/[-])
  • ARM MMIO Boot Drivers (Raspberry Pi 1, 2, 3, 4, 5) — Native VideoCore Mailbox initialization (Channel 8 properties), PL011 UART console mirror, DWC2 USB / SMSC9118 Ethernet stubs, and BCM2712 / RP1 south-bridge ABI mappings for Pi 5
  • x86_64 UEFI SMP (core_smp.c) — Cleanroom UEFI implementation: GOP framebuffer discovery, ACPI 6.5 XSDT/MADT parser, LAPIC MMIO (0xFEE00000), 16-bit AP trampoline at 0x9000, and INIT-SIPI-SIPI multi-core rendezvous
  • Authentic PC-98 i386 Real-Mode Boot (boot_pc98.c) — Full NEC PC-9801/PC-9821 support: planar VRAM text splash at 0xA0000/0xA2000, INT 1Ah RTC clock reads, INT 2Fh BTRON protocol handshake, A20 gate activation via port 0xF2, and 32-bit Protected Mode transition
  • Multi-OS & Unikernel Card Registry — Instant boot targets for B-System BTRON3, T-Kernel 2.0, seL4 Microkernel, NetBSD 11.0 (smolBSD MICROVM), PC-98 Linux 7.1, NEC V30 os8088, NuttX 12.0, FreeRTOS, and Erlang/OCaml unikernels
  • Emergency T-Monitor Fallback — Direct failover to low-level T-Monitor shell ([S]) upon kernel fault or invalid device tree configuration

Boot Architecture: Direct Multiboot & Hardware Discovery

Unlike conventional PC operating systems that rely on complex two-stage stage1/stage2 boot blocks (e.g. GRUB MBR/VBR), B-System uses a direct Multiboot-compliant single-stage binary architecture. The compiled ELF image (btron-uchida.elf or btron-morris.elf) is directly loaded by hypervisors and firmware into RAM at 1 MB.

2ステージ・ローダーの撤廃とダイレクトMultiboot機構： 従来の2段階ローダー（MBR/VBRステージ1→ステージ2）を介さず、core_boot.c 内のMultibootヘッダ（0x1BADB002）によりファームウェア/QEMUから1MBメモリ空間へ直接展開。固定モック文字列を排除し、MSRレジスタ（0x1B）、CPUID、IO-APIC、HPET、およびPC-98固有ポート（0xF2）からハードウェア実値を直接読み出して起動シーケンスを進行します。

Purpose & Architectural Features of Supported Kernels

Each kernel target serves an essential architectural niche within the B-System operating system lineage, ranging from instant workstation debugging to safety-critical hardware control:

  • Target 0: POSIX Microkernel Desktop (btron-posix / make run-posix) — Purpose: Zero-overhead host development, testing, and continuous integration without virtualization. Features: Bridges μITRON real-time task management (cre_tsk, sta_tsk, slp_tsk, wup_tsk, semaphores) onto native POSIX threads (pthreads). Routes BTRON Display Primitives (DP) vector and raster calls into an SDL2 window buffer, delivering instant sub-second desktop boot and test verification on macOS, Linux, and BSD.
  • Target 1: QEMU VirtIO Desktop (btron-qemu.elf / make run-qemu) — Purpose: Standardized hypervisor-agnostic cloud virtualization and portable testing. Features: Built around the paravirtualized VirtIO 1.4 specification on ARM Cortex-A7 (QEMU virt). Implements MMIO-based VirtIO GPU display drivers, VirtIO Tablet absolute pointer input, VirtIO Serial Console, and VirtIO Net network adapters, liberating the TRON desktop from proprietary SoC peripheral hardware locks.
  • Target 2: Raspberry Pi 2B Bare-Metal & Host Engine (btron-arm-baremetal.elf / make run-kernel & btron-tkernel.elf / make kernel) — Purpose: Direct bare-metal real-time execution on 32-bit ARM silicon without an intermediate OS, paired with an instant SDL2 host simulation testbed. Features: The bare-metal ELF boots natively on Broadcom BCM2836 (Cortex-A7 quad-core), configuring the VideoCore IV GPU Mailbox property channel (Channel 8) for 32-bit truecolor linear framebuffer rendering, programming the ARM Generic Interrupt Controller (GIC), managing hardware MMU page tables, and interfacing with PL011 UART. The companion host executable (btron-tkernel.elf) maps the complete T-Kernel 2.0 task scheduler, semaphore, and mailbox primitives onto the host display compositor with pixel-accurate ARGB8888 rendering for rapid prototyping.
  • Target 3: Sakamura T-Kernel 2.0 Desktop (btron-sakamura.elf / make run-sakamura) — Purpose: The canonical reference workstation pairing Sakamura's formal T-Kernel 2.0 real-time kernel with the authentic BTRON3 Human-Machine Interface (HMI). Features: Boots into the iconic Cho-Kanji teal workspace, featuring dual-bordered retro window managers, window z-ordering, live event queues, multilingual TRON code glyph engines, and the legendary Real Object / Virtual Object (実身／仮身) hyper-data filing system.
  • Target 4: x86_64 UEFI SMP Workstation (btron-uchida.elf / make run-uefi) — Purpose: Modern 64-bit PC workstation and hypervisor boot without legacy BIOS dependencies. Features: Loads via Multiboot single-stage entry directly at 1 MB into long mode. Performs native ACPI 6.5 table traversal (XSDT/MADT), discovers linear framebuffers via UEFI Graphics Output Protocol (GOP), configures Local APIC (LAPIC at 0xFEE00000) and I/O-APIC registers, executes a 16-bit real-mode AP trampoline at physical memory 0x9000, and orchestrates INIT-SIPI-SIPI multi-core scheduling and core scaling.
  • Target 5: NEC PC-9801 / PC-9821 VM (btron-morris.elf / make run-pc98) — Purpose: Authentic retrocomputing execution on Japan's legendary standard personal computer platform. Features: Interfaces directly with NEC PC-98 planar VRAM text and graphics planes (0xA0000 / 0xA2000), programs the NEC Graphic Display Controller (GDC), handles INT 1Ah RTC real-time clock queries, supports the INT 2Fh BTRON protocol handshake, triggers the PC-98 A20 gate via I/O port 0xF2, initializes the master/slave 8259A PICs, and smoothly transitions from 16-bit real mode into 32-bit protected mode.
  • Target 6: Raspberry Pi 4B AArch64 Bare-Metal (btron-aarch64-baremetal.elf / make run-yoko) — Purpose: Next-generation 64-bit bare-metal ARM computing for modern embedded workstations and edge nodes. Features: Targets the Broadcom BCM2711 (Cortex-A72 quad-core). Boots cleanly in ARMv8 AArch64 Exception Level 1/2, establishes 4-level 64-bit virtual memory translation paging (TTBR0/TTBR1), interfaces with the VideoCore VI mailbox, and scales T-Kernel 2.0 preemptive task scheduling across high-frequency 64-bit multicore clusters.

Pioneer Tributes & Kernel Naming Lineage

Operating systems do not emerge in isolation—they stand upon decades of dedicated research, architectural vision, and community craft. In B-System, every kernel target carries the name of a pioneering architect whose contributions to TRON, real-time microkernels, open-source firmware, and computer preservation are commemorated here.


Dr. Ken Sakamura (坂村 健) — Target 3: sakamura
Professor Emeritus, The University of Tokyo · Dean of INIAD, Toyo University · Chair of TRON Forum · ITU150 Award Laureate

In 1984, Dr. Ken Sakamura founded the TRON Project (The Real-time Operating system Nucleus) with an audacious philosophy: "Open Architecture" and "Ubiquitous Computing"—long before either term entered popular vocabulary. Dr. Sakamura envisioned computers embedded in everyday objects communicating collaboratively, and he insisted that TRON specifications remain free, royalty-free, and open to all manufacturers. He designed the fundamental architectures: ITRON (embedded real-time microkernel, today the most deployed RTOS in human history with billions of running instances), BTRON (business workstation with the revolutionary Real Object / Virtual Object hypermedia model), CTRON (telecom communications), and later T-Kernel.
In recognition of his foundational impact on global telecommunications and computing alongside Bill Gates, Robert Kahn, Thomas Wiegand, and Tim Berners-Lee, Dr. Sakamura was awarded the prestigious ITU150 Award by the United Nations International Telecommunication Union in 2015. Target 3 (sakamura) honors the father of TRON by preserving his pristine T-Kernel 2.0 and Cho-Kanji workstation design.
Prof. Hiroaki Takada (高田 広章) — Target 0: posix
Professor at Nagoya University · Founder & Chairman of the TOPPERS Project · Lead Architect of Open ITRON

Prof. Hiroaki Takada has been the foremost champion of open-source real-time operating systems in Japan. Through the creation of the TOPPERS Project (Toyohashi Open Platform for Embedded Real-time Systems), Prof. Takada led the development of world-class, production-grade open-source implementations of μITRON and OSEK/AUTOSAR specifications (including TOPPERS/JSP, TOPPERS/HRP, and TOPPERS/FMP for multicore processors). Crucially, Prof. Takada pioneered techniques for hosting ITRON task schedulers inside standard POSIX and Linux host environments, enabling generations of university students and automotive engineers to simulate, debug, and develop real-time systems on ordinary PCs without costly specialized hardware in-circuit emulators. Target 0 (posix / Takada) is a direct tribute to this legacy, mapping μITRON onto host POSIX threads.
Takahiro Yokobayashi (横林 貴広) — Targets 2 & 6: arm-elf / kernel & arm64-elf
Master Embedded Systems Engineer · Architect of the Bare-Metal Raspberry Pi T-Kernel 2.0 & T2EX Port

Bringing an industrial-grade real-time operating system to bare-metal consumer hardware requires deep mastery of low-level assembly, clock trees, cache coherency, and peripheral MMIO registers. Takahiro Yokobayashi achieved the monumental engineering feat of porting Sakamura's official T-Kernel 2.0 and T2EX (T-Kernel 2.0 Extended Extension) directly to the Raspberry Pi family (BCM2835, BCM2836 Pi 2B, BCM2837 Pi 3, and BCM2711 Pi 4B). His open contributions—authoring the startup assembly (icrt0.S), system timers, interrupt dispatcher, VideoCore mailbox drivers, and PL011 UART console subsystems—transformed the Raspberry Pi into an authentic, accessible bare-metal TRON workstation for experimenters and students around the globe. Targets 2 and 6 (arm-elf / btron-tkernel.elf and arm64-elf / Yokobayashi) stand as an enduring tribute to his hardware craftsmanship.
Kota Uchida (内田 公太) — Target 4: uefi
Author of 『ゼロからのOS自作入門』 ("Developing an OS from Scratch") · Creator of MikanOS · Modern UEFI OS Pioneer

For decades, operating system education was chained to archaic 16-bit IBM PC BIOS interrupts, MBR bootsectors, and legacy VGA text modes. Kota Uchida revolutionized Japanese operating system craftsmanship by writing the acclaimed textbook "Developing an OS from Scratch" and creating MikanOS. Uchida-san demonstrated how modern bare-metal systems can cleanly boot through 64-bit UEFI firmware, utilize linear Graphics Output Protocol (GOP) framebuffers, communicate via xHCI USB host controllers, and handle multicore SMP scheduling without any legacy BIOS crutches. Target 4 (uefi / btron-uchida.elf) honors Kota Uchida by implementing a cleanroom 64-bit UEFI SMP kernel with ACPI MADT parsing and multi-core AP trampoline initialization.
Hiroshi Tokita (常田 浩) — Target 1: qemu
Embedded Systems Architect · Open-Source RTOS & VirtIO Contributor to TOPPERS, Zephyr, and NuttX

Hiroshi Tokita has been an indispensable force in bridging Japanese RTOS standards with modern international open-source hypervisors and virtualization stacks. Through extensive contributions to TOPPERS, the Zephyr Project, and Apache NuttX, Tokita-san pioneered modern QEMU board virtual targets and VirtIO device driver frameworks for embedded microkernels. His efforts proved that real-time operating systems can achieve microsecond determinism while leveraging cloud hypervisors and standardized paravirtualized I/O. Target 1 (qemu / Tokita) honors Hiroshi Tokita by pairing cleanroom TRON graphics with standard VirtIO GPU and Tablet peripherals.
Awe Morris (森 あえ) — Target 5: pc98
Systems Craftsman & Firmware Architect · PS5 Boot Firmware & NPU Compiler Architect · zedBSD PC-98 Port · Suika Engine

A self-taught systems craftsman of rare breadth and humility, Awe Morris embodies the genuine hacker ethos of Japanese computing. Driven by a lifelong passion for computer science from early youth, his deep intuition for low-level architecture led to early breakthroughs in distributed memory systems and high-performance computing. Over more than two decades of versatile engineering, Morris has made quiet yet foundational contributions across the technological landscape — spanning parallelizing compilers, FPGA AI acceleration, creative tools like the Suika engine, next-generation NPU architectures, and mission-critical (PS5) boot firmware R&D at Sony Interactive Entertainment (SIE).

In Japanese operating system and retrocomputing history, Morris is revered for his seminal work porting zedBSD to the NEC PC-9801/PC-9821. His meticulous documentation of planar VRAM architectures, port 0xF2 gating, and timing-sensitive hardware quirks laid indispensable groundwork for modern PC-98 emulation and hypervisor support. Giving back warmly by mentoring aspiring programmers in the community, Target 5 (pc98 / btron-morris.elf) stands as a heartfelt tribute to his quiet brilliance, technical integrity, and enduring devotion to classic computing.

Typical Workflow

  1. Within 50 ms of system power-on, Bootloader activates the native display (GOP on UEFI, VideoCore mailbox on Pi, planar VRAM on PC-98).
  2. The Ski menu presents available operating systems, unikernels, and hardware targets — use [↑/↓] or [W/S] to highlight an entry.
  3. Press [E] to customize boot arguments (e.g., console baud rate, root filesystem, memory limits) or press [+]/[-] to scale allocated CPU cores.
  4. Press [Enter] to boot — on SMP systems, Ski coordinates all AP cores via LAPIC SIPI sequences before leaping into the kernel entry point.
  5. Boot handoff completes and control transfers seamlessly to the selected operating system kernel and BTRON workstation shell.
