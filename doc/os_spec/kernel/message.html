1.2.1 Огляд міжпроцесних повідомлень (Overview)

Кожен процес володіє системною чергою повідомлень, через яку здійснюється міжпроцесний обмін даними. Ця підсистема використовується як для зв'язку між прикладними програмами, так і для надсилання системних сповіщень ядра (наприклад, повідомлень про завершення дочірніх процесів).

Повідомлення адресуються в чергу цільового процесу за його унікальним PID. Процес-відправник також однозначно ідентифікується за своїм PID. Процес-відправник також однозначно ідентифікується за своїм PID.

1.2.3 Обробники повідомлень (Message Handlers)

Обробник повідомлень (Message Handler) — це функція, призначена для асинхронної обробки отриманих повідомлень паралельно з основним потоком виконання програми. Обробники реєструються шляхом зв'язування типу повідомлення з відповідною функцією. Таким чином, у системі можна одночасно визначити до 31 незалежного обробника (по одному для кожного з 31 типів повідомлень).

Обробники повідомлень викликаються та виконуються у наступних випадках:

  • При надходженні повідомлення відповідного типу обробник викликається асинхронно у формі переривання поточної роботи головної задачі процесу.

  • Якщо повідомлення надходить у момент, коли головна задача перебуває у стані очікування (заблокована системним викликом), обробник також негайно активується, переводячи головну задачу в стан виконання (Run).
    У цьому випадку заблокований системний виклик очікування безумовно переривається, а після завершення обробника даний виклик повертає код помилки ER_MINTR.

  • Обробник повідомлень виконується у загальному адресному просторі та контексті процесу і не має обмежень на використання інших системних викликів.

  • Після завершення обробника виконання головної задачі зазвичай автоматично відновлюється з точки переривання. Проте обробник може виконати прямий перехід за допомогою виклику longjmp() у будь-яку довільну точку коду, попередньо збережену викликом setjmp().

  • Обробники повідомлень не є вкладеними. Якщо під час виконання обробника надходить нове повідомлення (навіть іншого типу), його обробник буде заблокований у черзі до повного завершення поточного обробника.

  • При активації обробника відповідне повідомлення вилучається з черги повідомлень, а вказівник на нього разом із PID відправника передаються як параметри функції обробника.

  • Обробник повідомлень обов'язково повинен завершуватися викликом системного функціоналу ret_msg().

Функція обробника повідомлень визначається за наступною сигнатурою C: 

    VOID msg_hdr(W pid, MESSAGE *r_msg)
    {
        /* pid — ідентифікатор процесу-відправника (0 якщо відправник — власний процес) */
        /* r_msg — вказівник на структуру прийнятого повідомлення */

        /* Обробка прийнятого повідомлення */

        ret_msg (0);            /* Завершення (повернення в точку переривання) */

        /* АБО */

        ret_msg (1);            /* Завершення (перехід за заздалегідь збереженою адресою) */
        longjmp (reent, code);  /* Прямий перехід у точку reent */
    }

Система надає наступні 3 готові системні обробники за замовчуванням:

MH_NONE :

Повідомлення ігнорується без виконання дій. Виняток: блокуючі системні виклики очікування при цьому НЕ перериваються. Застосовується для повного ігнорування повідомлень певного типу без занесення їх у чергу.

MH_BREAK :

Повідомлення ігнорується, але заблоковані системні виклики очікування перериваються і повертають код помилки ER_MINTR. Використовується для переривання очікування при таймаутах.

MH_TERM :

Аварійно завершує поточний процес та надсилає батьківському процесу системне повідомлення MS_ABORT з кодом помилки 0.

1.2.5 Системні виклики обміну повідомленнями (Message System Calls)

snd_msg
 
Надсилання міжпроцесного повідомлення (Send Message)

【Синтаксис / Прототип】

ERR     snd_msg(W pid, MESSAGE* msg, W opt)

【Параметри】

W        pid  PID процесу-отримувача ( > 0 або 0 для власного процесу)
MESSAGE* msg  Вказівник на структуру надсиланого повідомлення
W        opt  Опції надсилання (0 або WAIT_CLR / WAIT_ERR)

【Значення, що повертається】

= 0      Успішне виконання
< 0      Помилка (Код помилки)

【Детальний опис】

Надсилає повідомлення msg у системну чергу повідомлень цільового процесу pid. Якщо черга отримувача заповнена, відправник заблоковується до появи вільного місця або повертає помилку залежно від прапорця opt.

【Коди помилок】

ER_ID       : Неіснуючий PID отримувача.
ER_ADR      : Неприпустима адреса буфера msg.
ER_LIMIT    : Черга повідомлень отримувача заповнена (при неблокуючому режимі).
ER_PAR      : Неприпустимий параметр типу чи розміру повідомлення.
rcv_msg
 
Прийом повідомлення з черги (Receive Message)

【Синтаксис / Прототип】

WERR    rcv_msg(MESSAGE* r_msg, W t_mask, W time)

【Параметри】

MESSAGE* r_msg   Буфер для збереження прийнятого повідомлення
W        t_mask  Маска типів повідомлень (Type Mask)
W        time    Максимальний інтервал очікування в мілісекундах (-1 для нескінченного очікування)

【Значення, що повертається】

> 0      Успішне виконання (PID відправника прийнятого повідомлення)
< 0      Помилка (Код помилки)

【Детальний опис】

Вилучає з власної черги повідомлень наступне повідомлення, що відповідає масці типів t_mask, та скопіює його у буфер r_msg. Якщо підходящі повідомлення відсутні, задача чекає до надходження повідомлення або спливання таймауту time.

【Коди помилок】

ER_NOMSG    : У черзі немає повідомлень вказаного типу (при неблокуючому прийомі).
ER_MINTR    : Очікування переривано у зв'язку з активацією обробника повідомлень.
ER_ADR      : Неприпустима адреса буфера r_msg.
clr_msg
 
Очищення черги повідомлень (Clear Messages)

【Синтаксис / Прототип】

WERR    clr_msg(W t_mask)

【Параметри】

W   t_mask  Маска типів повідомлень для видалення

【Значення, що повертається】

>= 0     Успішне виконання (кількість видалених з черги повідомлень)
< 0      Помилка (Код помилки)

【Детальний опис】

Видаляє та очищає з власної черги повідомлень усі накопичені повідомлення, типи яких відповідають масці t_mask.

【Коди помилок】

ER_PAR      : Неприпустима маска t_mask.
req_tmg
 
Запит таймерного повідомлення (Request Timer Message)

【Синтаксис / Прототип】

WERR    req_tmg(W time, W code)

【Параметри】

W   time    Інтервал спрацьовування таймера в мілісекундах
W   code    Корисний код, що передається у повідомленні MS_TIMEOUT

【Значення, що повертається】

> 0      Успішне виконання (ідентифікатор створеного таймера)
< 0      Помилка (Код помилки)

【Детальний опис】

Реєструє системний таймер, який після спливання інтервалу time надсилає у чергу власного процесу повідомлення MS_TIMEOUT з кодом code.

【Коди помилок】

ER_LIMIT    : Перевищено системний ліміт активних таймерів.
ER_PAR      : Неприпустимий параметр часу time (time <= 0).
can_tmg
 
Скасування таймерного повідомлення (Cancel Timer Message)

【Синтаксис / Прототип】

ERR     can_tmg(W tmgid)

【Параметри】

W   tmgid   Ідентифікатор таймера, отриманий при виклику req_tmg()

【Значення, що повертається】

= 0      Успішне виконання
< 0      Помилка (Код помилки)

【Детальний опис】

Скасовує раніше зареєстрований системний таймер tmgid і зупиняє надсилання таймерного повідомлення.

【Коди помилок】

ER_ID       : Неіснуючий або вже скасований ідентифікатор таймера tmgid.
def_msg
 
Реєстрація обробника повідомлень (Define Message Handler)

【Синтаксис / Прототип】

ERR     def_msg(W msg_type, FP msg_hdr)

【Параметри】

W   msg_type  Тип повідомлення (1..31)
FP  msg_hdr   Вказівник на функцію обробника або системні константи MH_NONE, MH_BREAK, MH_TERM

【Значення, що повертається】

= 0      Успішне виконання
< 0      Помилка (Код помилки)

【Детальний опис】

Зв'язує тип повідомлення msg_type з вказаною функцією обробника msg_hdr або встановлює системні обробники за замовчуванням (MH_NONE, MH_BREAK, MH_TERM).

【Коди помилок】

ER_PAR      : Неприпустимий тип повідомлення msg_type або вказівник msg_hdr.
ret_msg
 
Завершення виконання обробника (Return Message Handler)

【Синтаксис / Прототип】

VOID    ret_msg(W mode)

【Параметри】

W   mode    Режим завершення обробника (0: повернення в точку переривання, 1: перехід longjmp)

【Значення, що повертається】

Функція не повертає значення (відновлює потік або виконує transition).

【Детальний опис】

Завершує функцію обробника повідомлень та повертає головну задачу процесу у точку переривання (при mode = 0) або дозволяє виконати перехід longjmp() (при mode = 1).

【Коди помилок】

Помилок немає.

brk_msg
 
Переривання очікування повідомлення (Break Message Waiting)

【Синтаксис / Прототип】

ERR     brk_msg(W tskid)

【Параметри】

W   tskid   Ідентифікатор заблокованої задачі

【Значення, що повертається】

= 0      Успішне виконання
< 0      Помилка (Код помилки)

【Детальний опис】

Примусово перериває виклик rcv_msg() у вказаній заблокованій задачі tskid. Виклик rcv_msg() переривається і повертає код помилки ER_MINTR.

【Коди помилок】

ER_ID       : Неіснуючий tskid або задача не перебуває у стані очікування rcv_msg().
