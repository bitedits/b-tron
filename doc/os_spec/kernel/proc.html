1.1 Процеси та потоки / タスク管理

Процеси та потоки / タスク管理機能では、 シングルユーザ / マルチПроцеси та потокиのシステムを実現するために必要な各種の機能を提供している。

1.1.1 Процеси та потоки / タスク

Процеси та потокиとはプログラムを OS が管理する単位であり、 1 つのマシン上に複数のПроцеси та потокиが存在する。

タスクとはプログラムの実行単位であり、 1 つのПроцеси та потокиには 1 つまたは複数のタスクが存在し、 優先度順および時分割のスケジューリングにより同時に実行される。

1 つのПроцеси та потокиは基本的に下図に示すような独立したアドレス空間を持つ。

図 1 : Процеси та потокиの基本メモリモデル

Процеси та потокиは、対象となる実行プログラムファイルを指定して生成され、 生成時に割り付けられるПроцеси та потоки ID により識別される。 Процеси та потоки ID は、正の整数値であり、 その割り付け方法は若い番号から順番に割り付けられる。

Процеси та потокиが生成されると、 メインタスクが実行を開始する。 メインタスクによってサブタスクを起動することで、 1 つのПроцеси та потоки内に複数のタスクが存在する状態になる。 つまり、Процеси та потокиには 1 つのメインタスクと 0 個以上のサブタスクが同時に存在する。

メインタスクとサブタスクを総称してタスクと呼ぶ。 タスクはタスクIDにより識別される。 タスクIDは正の整数となる。

システムの立上げ時に、まず初期Процеси та потокиが生成され、 初期Процеси та потокиが順次必要なПроцеси та потокиを生成していくことになる。 自分が生成したПроцеси та потокиを子Процеси та потокиと呼び、 自分を生成してくれたПроцеси та потокиを親Процеси та потокиと呼ぶ ( 初期Процеси та потокиの親Процеси та потокиは存在しない )。 従って、システム全体としては、 初期Процеси та потокиをルートとする木構造のПроцеси та потоки構造をとる。

あるПроцеси та потокиが終了した場合には、 その子Процеси та потокиの親Процеси та потокиは終了したПроцеси та потокиの親Процеси та потокиに入れ換り、 全体として木構造は保たれることになるが、 例外的に初期Процеси та потокиが終了した場合には、 その子Процеси та потокиの親Процеси та потокиは存在しない状態となる。

1.1.2 Процеси та потоки / タスクの状態

Процеси та потокиの状態として以下の 4 つの基本状態が定義される。
Процеси та потокиの状態は、メインタスクの状態である。

未生成状態 (Non-Existent)-- Процеси та потокиは生成されていない状態
実行可能状態(Ready) -- 実行可能でディスパッチ待ち状態
実行状態 (Run) -- 実行中状態
待ち状態 (Wait) -- Повідомлення、時間、入出力等の待ち状態

Процеси та потокиの各状態は各種のシステムコールや、 スケジューリング ( ディスパッチ、プリエンプト ) により以下のように遷移する。

1.1.3 Процеси та потоки / タスクの優先度とスケジューリング

Процеси та потокиには、生成時に 0 〜 255 ( 0 が最高優先度 ) の優先度が与えられる。 この優先度はメインタスクの優先度となる。 Процеси та потоки優先度と言った場合、それはメインタスクの優先度と等価である。 各Процеси та потокиはその優先度により、下記の3つのグループに分類される。

また、サブタスクにもタスク生成時に優先度が与えられる。

各タスクは、その優先度に従ってスケジューリングが行なわれる。

A. 絶対優先度グループ (優先度: 0〜127)

厳密に優先度順にスケジューリングされ(0が最高優先度)、 同一優先度の場合は、 ラウンドロビン方式で平等にスケジューリングされる。

B. ラウンドロビングループ1 (優先度: 128〜191)

このグループ内全体でラウンドロビンスケジューリングが行なわれ、 優先度は相対的なスケジューリングの頻度を示す (128が最高優先度) 。
従って、優先度が低いタスクでも必ず実行されることが保証される。

C. ラウンドロビングループ2 (優先度: 192〜255)

このグループ内全体でラウンドロビンスケジューリングが行なわれ、 優先度は相対的なスケジューリングの頻度を示す (192が最高優先度)。
従って、優先度が低いタスクでも必ず実行されることが保証される。

実際のスケジューリングは、全体として以下のように行なわれる。

  1. 絶対優先度グループに属する実行可能状態のタスクがあれば、 その中の最高優先度のタスクを実行状態とし、 実行する。なければ、2. へ進む。

  2. ラウンドロビングループ 1 に属する実行可能状態のタスクがあれば、 その中の相対優先度に従って、 選択されたタスクを実行状態とし、 実行する(最高優先度とは限らない)。 なければ、2. へ進む。

  3. ラウンドロビングループ 2 に属する実行可能状態のタスクがあれば、 その中の相対優先度に従って、選択されたタスクを実行状態とし、 実行する(最高優先度とは限らない)。 なければ、スケジューリングを始めからやり直す。

通常、絶対優先度グループは、システムПроцеси та потокиやリアルタイムПроцеси та потокиに使用され、 一般のアプリケーションПроцеси та потокиはラウンドロビングループ 1、または 2 を使用する。

一度生成されたПроцеси та потоки / タスクの優先度の変更は、 同一グループ内でのみ可能であり、 グループが異なる優先度への変更はできない。

1.1.5 ユーザ情報

ユーザ情報は、 そのПроцеси та потокиを生成して使用しているユーザに関する情報であり、 以下に示す内容を持つ。

ユーザ名 :

ユーザの名称であり、12 文字の名前の後に 2 文字分 ( 32 ビット ) の隠し名を付けたものである。 12 文字より少ない名前の場合は 0 がパッドされ、名前が存在しない場合は、14 文字がすべて 0 となる。

所属グループ名 ( 1 〜 4 ) :

ユーザが所属する 4 つのグループの名称であり、 それぞれ 12 文字の名前の後に 2 文字分 ( 32 ビット) の隠し名を付けたものである。 12 文字より少ない名前の場合は 0 がパッドされ、 名前が存在しない場合は、14 文字がすべて 0 となる。

ユーザレベル :

ユーザの特権レベルであり、0 〜 15 の範囲の値を取り、 0 が最高レベルとなる。

ネットワークユーザレベル :

ネットワーク経由で他のマシンをアクセスする場合のユーザレベルで、 1 〜 15 の範囲の値を取り、 1 が最高レベルである。この場合、 ネットワークユーザレベルの 0 は適用されない。

ファイルのデフォールトアクセスモード :

ファイルを生成する場合のデフォールトのアクセスモード。

ユーザ情報は、 以下に示す構造体で定義され、 システムコールにより取出し / 設定が可能である。 ただし、隠し名を取り出すことはできず、 隠し名の部分には常に 0 が得られることになる。 

typedef struct {
    TC  usr_name[14];   /*ユーザ名(12文字＋隠し名2文字)*/
    TC  grp_name1[14];  /*グループ名1(12文字＋隠し名2文字)*/
    TC  grp_name2[14];  /*グループ名2(12文字＋隠し名2文字)*/
    TC  grp_name3[14];  /*グループ名3(12文字＋隠し名2文字)*/
    TC  grp_name4[14];  /*グループ名4(12文字＋隠し名2文字)*/
    W   level;          /*ユーザレベル(0〜15)*/
    W   net_level;      /*ネットワークユーザレベル(1〜15)*/
} P_USER;

初期Процеси та потокиのユーザ情報は、当初はシステムで定義された固定的な内容を持つが、 その後、ユーザーが確定した時点で、実際のユーザ情報が設定されることになる。

1.1.6 Процеси та потокиの生成

Процеси та потокиの生成は、対象とするファイル、Процеси та потокиの優先度、 およびПроцеси та потокиに渡すПовідомленняを指定することにより行なわれる。

指定したファイル内の最初の実行プログラムレコードの内容が生成するПроцеси та потокиのプログラムコードとなる。 実行プログラムレコードは、先頭レコードでなければならない。

Процеси та потокиに渡すПовідомленняは以下のПовідомлення構造体へのポインタで指定される。 これはПроцеси та потоки間Повідомленняと同一の構造を持つ。 

typedef struct {
    W   msg_type;       /*Повідомленняタイプ*/
    W   msg_size;       /*Повідомленняサイズ(バイト数)*/
    UB  msg_body[n];    /*Повідомлення本体(msg_size バイト)*/
} MESSAGE;

生成されたПроцеси та потокиは以下に示す2つのどちらかの形式により、 Повідомленняを受け取ることができる ( ただし、形式-B は、実際にはライブラリとして実現される )。
MAIN() および main() からのリターンはПроцеси та потокиの終了となり、 ext_prc() による終了と同等である。 終了コードは、正常終了Повідомленняに設定され、親Процеси та потокиに通知される。

□ 形式-A

W MAIN (MESSAGE *msg)
    /*  MESSAGE *msg;      Повідомленняへのポインタ*/
{
    < プログラムの実行コード >
    return 終了コード;
}
  • 生成時に指定したПовідомленняを直接的に得る基本形式。
    msg_type に無関係にすべてのПовідомленняを受け取ることが可能。

□ 形式-B

W main (W ac, TC **argv)
     /* W     ac;         文字列項目数*/
     /* TC    **argv;     文字列項目のポインタ配列へのポインタ*/
{
    < プログラムの実行コード >
    return 終了コード;
}

  • 生成時に指定したПовідомленняの msg_type = 0 の場合にのみ、 この形式が適用可能で、この場合は msg_body[] は TNULL で終了する 1 つの文字列と見なされる。 文字列は空白で区切られ、複数の項目に分解される。 プログラムへは、各項目の文字列へのポインタの配列として渡されることになる。

  • msg_body[] が TNULL で終了していない場合は、 最後の文字は TNULL と見なされる。

  • この形式の場合は、生成時に指定されたПовідомленняの msg_type ≠ 0 の時は、ac= 0, *argv＝NULL となり、 Повідомленняを受け取ることはできない。

1.1.7 Процеси та потоки / タスクの実行

Процеси та потокиは複数のタスクで構成されるため、 各タスクが同時並行的に動作することができる。 タスクは、プログラムの流れに沿って実行されるが、 例外的に以下のハンドラ(関数)は非同期に割り込んで実行される。

Повідомленняハンドラ

Повідомлення受信により非同期に実行される関数。

例外処理ハンドラ

自Процеси та потоки内の例外発生により非同期に実行される関数。

これらの関数はいずれもПроцеси та потокиの一部として、 そのПроцеси та потокиのメモリ空間、および環境の下で実行され、 使用可能なシステムコール等の制限は特にない。 実行終了後は、割り込まれた位置に戻るか、 または任意の位置に直接ジャンプすることができる。

Повідомленняハンドラの詳細に関しては「1.2.3 Повідомленняハンドラ」を、 例外処理ハンドラの詳細に関しては「1.10 Системне управління機能」を参照のこと。

また、Процеси та потокиはその実行時に以下のようなПроцеси та потоки統計情報を得ることができる。 

typedef struct {
    UW  etime;      /*累計経過時間 (秒単位)*/
    UW  utime;      /*Процеси та потокиで費やした累計CPU時間*/
    UW  stime;      /*システムで費やした累計CPU時間*/
    W   tmem;       /*実行に必要とする全体のメモリサイズ*/
    W   wmem;       /*現在割り付けられている実メモリサイズ*/
    W   resv[11];   /*予約*/
} P_INFO;

utime と stime は、Процеси та потокиに含まれる、 その時点で存在するすべてのタスクの合計時間となる。 したがって、それ以前に終了したタスクが費やした時間は含まれない。 utime と stime を合計したものが、 そのПроцеси та потокиが費やした累積 CPU 時間となる。

1.1.9 システムコール

cre_prc
 
Процеси та потоки生成 / 実行

【形式】

WERR    cre_prc(LINK* lnk, W pri, MESSAGE* msg)

【パラメータ】

LINK*    lnk  対象実身

W        pri  Процеси та потоки優先度
              0 ≦ pri ≦ 255  任意の優先度
              = -1             自Процеси та потокиと同じ優先度
MESSAGE* msg  Процеси та потоки起動時Повідомлення

【リターン値】

＞0    正常(生成したПроцеси та потоки ID)
＜0    エラー(エラーコード)

【解説】

指定した実身内の実行プログラムレコードを、 新しいПроцеси та потокиとして生成する。 同時にメインタスクが生成され実行を開始する。

「1.1.6 Процеси та потокиの生成」を参照のこと。

【エラーコード】

ER_ACCES    : ファイル(lnk)のアクセス権(E)がない。
ER_ADR      : アドレス(lnk,msg)のアクセスは許されていない。
ER_BUSY     : ファイル(lnk)は既に排他的にオープンされている為、
              同時にファイルをオープンすることができなかった。
ER_IO       : 入出力エラーが発生した。
ER_NOEXS    : ファイル(lnk)は存在していない。
ER_NOFS     : ファイル(lnk)の属するФайлова системаは接続されていない。
ER_NOMEM    : メモリ領域が不足した。
ER_NOSPC    : システムのメモリ領域が不足した(Процеси та потоки数が多すぎる)。
ER_PPRI     : 優先度の値が範囲外である(-1,-0〜255 以外)。
ER_REC      : ファイルにプログラムレコードは存在しない、
              またはプログラムレコードの内容が異常である。
ER_SZOVR    : Процеси та потоки起動Повідомленняのサイズがシステムの制限を越えた。
ext_prc
 
Процеси та потоки終了

【形式】

VOID    ext_prc(W code)

【パラメータ】

W   code    Процеси та потоки終了コード

【リターン値】

リターンしない

【解説】

自Процеси та потокиを正常終了し、 指定した code を含むПроцеси та потоки正常終了Повідомленняを親Процеси та потокиに送信する。

自Процеси та потокиで使用中のファイル等のリソースは一部のリソース ( cre_sem 等オプションに DELEXIT 指定がないもの)を除き、 すべて自動的に解放される。

【エラーコード】

発生しない。

        =  0   自Процеси та потоки(指定不可:エラー)
        = -1   親Процеси та потоки

W   code    強制終了コード

W   opt 強制終了属性
        ( TERM_NRM ‖ TERM_ALL )
        TERM_NRM    指定したПроцеси та потокиのみの強制終了。
        TERM_ALL    指定したПроцеси та потокиおよびその全ての子孫のПроцеси та потокиの強制
                    終了。親Процеси та потокиまたはさらにその親のПроцеси та потокиを指定し
                    た場合には、自Процеси та потокиも強制終了させられる。
                    この場合、指定したПроцеси та потокиの子孫の強制終了Повідомлення
                    は送信されない。

【リターン値】

＝0    正常
＜0    エラー(エラーコード)

【解説】

指定したПроцеси та потокиを強制終了し、 指定した code を含むПроцеси та потоки強制終了Повідомленняを指定したПроцеси та потокиの親Процеси та потокиに送信する。

自Процеси та потокиより高いユーザレベルのПроцеси та потокиは強制終了できない。

【エラーコード】

ER_SELF     : 自Процеси та потокиを指定した(pid = 0または自Процеси та потокиのPID)。
ER_NOPRC    : Процеси та потоки(pid)は存在していない。
ER_LEVEL    : 自Процеси та потокиより高いユーザレベルのПроцеси та потокиを指定した。
ER_PAR      : パラメータが不正である(opt=TERM_NRM,TERM_ALL以外を指定した)。
chg_pri
 
Процеси та потоки / タスク優先度変更

【形式】

WERR    chg_pri(W id, W pri, W opt)

【パラメータ】

W   id  対象Процеси та потоки ID またはタスク ID 

W   pri 変更する優先度

W   opt 優先度属性
        ( P_ABS ‖ P_REL ) | [ P_TASK ]
          P_ABS   絶対指定：指定した優先度に変更。
          P_REL   相対指定：(現在の優先度)＋pri に変更。
          T_TASK  タスクを対象とする。

【リターン値】

≧0    正常(変更後の優先度 0〜255)
          P_TASK 指定あり    id のタスクの優先度
          P_TASK 指定なし    id のПроцеси та потокиのメインタスクの優先度
＜0    エラー(エラーコード)

【解説】

指定したПроцеси та потоки / タスクの優先度を変更する。

P_TASK の指定がない場合 : 

id ＝  0     自Процеси та потоки内の全タスクの優先度を変更する。
id ＝ -1     親Процеси та потоки内の全タスクの優先度を変更する。
id ＞  0     id で指定したПроцеси та потоки ID のПроцеси та потоки内の全タスクの優先度を変更する。

P_TASK が指定された場合 

id ＝ 0      自タスクの優先度を変更する。
id ＞ 0      id で指定したタスク ID のタスクの優先度を変更する。
             指定できるタスクは、自Процеси та потоки内のタスクのみである。

指定できる優先度の範囲は、 対象タスクが属するПроцеси та потокиの現在の優先度グループ内となる。

【エラーコード】

ER_NOPRC    : Процеси та потоки(id)は存在していない。
ER_ID       : タスク(id)は存在していない。または、自Процеси та потоки内のタスクではない。
ER_PPRI     : 優先度の値が範囲外である(新優先度は現在優先度のグループ外)。
ER_PAR      : パラメータが不正である(opt=P_ABS,P_REL,P_TASK以外を指定した)。

cre_tsk
 
サブタスク生成 / 実行

【形式】

WERR    cre_tsk(FP entry, W pri, W arg)

【パラメータ】

FP  entry   サブタスク開始アドレス
W   pri     サブタスク優先度
W   arg     サブタスク起動パラメータ

【リターン値】

＞0    正常(生成したサブタスク ID)
＜0    エラー(エラーコード)

【解説】

自Процеси та потоки内のサブタスクを生成して実行する。

サブタスクの優先度は、自Процеси та потокиの優先度グループの範囲内でのみ指定できる。 サブタスクは以下の形式の関数として定義される。 

    VOID    subtask(W arg)
    {
        /* arg は cre_tsk() で指定したパラメータ */
        < サブタスクコード >
        /* タスク終了 */
        ext_tsk();
    }

サブタスクを return で終了することはできない。

【エラーコード】

ER_ADR      : アドレス(entry)が不正である。
ER_PPRI     : 優先度(pri)が自Процеси та потокиの優先度グループの範囲を超えている。
ER_LIMIT    : サブタスク数の制限を超えた。
ER_NOMEM    : メモリー領域が不足した。

【パラメータ】

【リターン値】
