3.6 データマネージャ

3.6.1 データマネージャのфункціонал / підсистема

3.6.1.1 概要

データマネージャは, 外殻の 1 つとして位置付けられ, HMI マネージャ群や, прикладний додаток / програмаプログラムで使用する固定的なデータ群をプログラムと切り離した«データボックス»として定義しておき, その内に存在するデータ項目を効率的かつ統一的に取り扱う手段を提供している. データマネージャ自体はデータボックスを作成するфункціонал / підсистемаは持たない.

データボックスは, 以下の 2 種に大別される.

  • システムデータボックス

    システムで標準的に共通使用するデータ群を登録した, システムに唯一存在するデータボックス.

  • прикладний додаток / програмаデータボックス

    прикладний додаток / програма(群)で固有に使用するデータ群を登録したデータボックスで, прикладний додаток / програма(群)毎に定義される.

1つのприкладний додаток / програмаは同時にシステムデータボックスと, 複数のприкладний додаток / програмаデータボックスを使用することができる.

3.6.1.2 データタイプID／データ番号

データボックスに登録されている 1 つのデータ項目は, データタイプIDとデータ番号で識別される. データタイプIDはデータのカテゴリを示すものであり, データ番号は 1 つのデータタイプ内でユニークに付けられた番号 ( > 0 ) である.

データタイプIDとしては以下のものが規定されている.

PTR_DATA ( 1)вказівник (Pointer)イメージ
PICT_DATA ( 2)ピクトグラムイメージ
PAT_DATA ( 3)パターンデータ
BMAP_DATA ( 4)図形ビットマップデータ
FIG_DATA ( 5)図形セグメントデータ
TEXT_DATA ( 6)文字列データ
PARTS_DATA( 7)コントロールパーツ定義データ
MENU_DATA ( 8)標準メニュー定義データ
GMENU_DATA( 9)汎用メニュー定義データ
PANEL_DATA(10)パネル定義データ
USER_DATA (64〜)ユーザ定義データ

ユーザ定義データは, 特定のприкладний додаток / програма(群)で使用されるデータタイプであり, 64 以上の任意のタイプIDをつけて使用することができる.

各データタイプID毎にデータ構造が定義されているが, 一部のタイプを除いてその内容はデータマネージャとしては関知しない.

3.6.1.3 データマネージャの動作

データマネージャを使用するために, прикладний додаток / програмаは, まず対象とするデータボックス ( システムデータボックスを含む ) をすべてオープンする. この結果, 各прикладний додаток / програма ( Процес (Process) ) 毎に対象とするデータボックスが別々に管理される. ただし, システムデータボックスはすべてのприкладний додаток / програмаで共通の対象となる.

прикладний додаток / програмаが, データタイプIDとデータ番号を指定して, データ項目の参照要求を行なった場合, データマネージャは, そのприкладний додаток / програмаがオープンしたデータボックスを順番にサーチして, 要求されたデータ項目が存在するか否かをチェックする. データボックスのサーチは, オープンした逆順に行なわれ, システムデータボックスは常に一番最後になる. 従って, 同一データタイプID, 同一データ番号を使用することにより, あるデータ項目をприкладний додаток / програма固有の別のデータ項目で再登録することができる.

要求されたデータ項目が存在する場合は, そのデータ項目を共有Оперативна пам'ять (Memory)上で参照できるようにしてそのОперативна пам'ять (Memory)адреса пам'ятіをприкладний додаток / програмаに戻す. 既に共有Оперативна пам'ять (Memory)上で参照できる状態にあった場合は単にその領域のадреса пам'ятіをприкладний додаток / програмаに戻すことになる. この場合は, 複数のприкладний додаток / програма間で, そのデータ項目を共用していることになる.

データマネージャにより共有Оперативна пам'ять (Memory)上にロードされたデータは, 他のприкладний додаток / програмаからも参照される可能性があるため, 直接変更してはいけない. 書き込みの保護はされていないため, прикладний додаток / програма側でこの点を注意しなくてはならない. 変更したい場合は, 別領域にコピーする必要がある.

3.6.1.4 データボックスの構造

データボックスはФайл (File)の1つのЗапис (Record)として定義される. Запис (Record)タイプは«データボックス»タイプとなる.

通常, 1 つのデータボックスは, 独立した 1 つのФайл (File)として定義されるが, 1 つのФайл (File)の中に複数のデータボックスを入れる場合や, 別のЗапис (Record)と混在している場合もある.

システムデータボックスは1つのФайл (File)として独立しており, 固定的なФайл (File)パスを持ち, прикладний додаток / програмаデータボックスはприкладний додаток / програмаがそのФайл (File)パスを指定するため, 基本的にどこに存在してもよいが, 通常は, прикладний додаток / програмаプログラムФайл (File)内に置くことが多い.

データボックスは大きくインデックス部とデータ部から構成され, 全体として以下に示す構造を持つ.

図 108 : 全体構造

インデックス部はヘッダと, そのデータボックスが含む各データタイプID毎のインデックスから構成され, 基本的にオープンされた時点でデータマネージャの管理するОперативна пам'ять (Memory)領域上にロードされる.

インデックス部はヘッダと, そのデータボックスが含む各データタイプID毎のインデックスから構成され, 基本的にオープンされた時点でデータマネージャの管理するОперативна пам'ять (Memory)領域上にロードされる.

ヘッダは16バイトの以下の構造を持つ. 

    typedef struct {
        H   ntyp;       /* ボックス内のデータタイプIDの数 */
        H   ixsize;     /* インデックス部の総バイト数 */
        H   resv[6];    /* 予約 */
    } DBOX_HDR;

各データタイプ毎のインデックスは, 以下の構造を持つ. 

    typedef struct {
        W   npos;        /* 次のタイプのインデックスへのオフセット */
        W   typ;         /* データタイプID */
        UW  attr;        /* データの属性(未使用) */
        W   nd;          /* このタイプに属するデータ項目の数 */
        DNUM_INX dix[1]; /* 項目インデックス配列 (nd 個の要素) */
    } DTYP_INX;
  • オフセットは, データボックスの先頭からのバイトオフセットである.
  • データの属性は以下の内容であり, そのタイプのすべてのデータ項目に適用される. 
        attr: xxxx .. xxxx xxxL
L: プレロード指定
1の場合は, データボックスのオープン時に, 含まれる全てのデータ項目を共有Оперативна пам'ять (Memory)ブロックにロードされる. プレロードされたデータ項目はオープンしたПроцес (Process)により参照されている状態となる.
0の場合は, オープン時にはロードせず, 実際の参照時に個別にロードされる.
x:
予約 (0)

項目インデックスは20バイトの, 各データ項目に対応するインデックスで, データ部に含まれるデータ本体へのオフセット, およびрозмір у байтахを保持している. 

    typedef struct {
        W   id;         /* データ番号 */
        W   pos;        /* 対応するデータ本体へのオフセット */
        W   size;       /* データ本体のバイトрозмір у байтах */
        W   info[2];    /* 内部使用領域 */
    } DNUM_INX;

1 つのデータボックスに入るインデックスの数に特に制限はないが, インデックス部全体のバイト数は 32K バイト以下でなくてはいけない. また, 同一タイプのインデックスが複数含まれていても問題ないが, なるべく 1 つにまとまっている事が望ましい.

データ本体はそのデータタイプに依存した構造を持つが, データマネージャは一部のデータタイプを除いて, その構造には関知せず, 単なるバイトデータ列として取り扱う.

パターンイメージは描画パターンとして使用されるイメージであり, ディスプレイプリミティブで使用される PATTERN と同様の構造を持っており, 以下の2種類のいずれかの構造となる.

図 109 : パターンイメージ

図 110 : 図形ビットマップイメージ

□ 文字列データ (TEXT_DATA)

3.6.3 データマネージャの関数

ここでは, データマネージャがサポートしている各関数の詳細を説明する. これらの関数群は, 外殻の拡張системний виклик (System Call)として提供される.

なお, データマネージャでは核のПроцес (Process)管理, Файл (File)管理, Оперативна пам'ять (Memory)管理を使用しているため, Помилкаが発生した場合は, Процес (Process)管理, Файл (File)管理, Оперативна пам'ять (Memory)管理のкод помилкиが直接戻る.

dopn_dat
 
データボックスのオープン

【Синтаксис / Прототип】

W   dopn_dat(LINK *lnk)

【Параметри】

LINK    *lnk    データボックスФайл (File)のПосилання (Link)

【Значення, що повертається】

>= 0     Успішне виконання終了(データボックスФайл (File)ID)
＜0    код помилки

【Детальний опис】

lnk で指定したФайл (File)に含まれるデータボックスをすべてオープンし, прикладний додаток / програмаПроцес (Process)からのデータボックスの参照を可能とする. 関数値として, オープンしたФайл (File)のID ( > 0 ) が戻される. このIDは データボックスのクローズ ( dcls_dat ) でのみ使用される.

システムデータボックスがそのПроцес (Process)に対して, まだオープンされていない場合は, 同時にシステムデータボックスも自動的にオープンされる. lnk = NULL の場合は, システムデータボックスのみのオープンとなり, 関数値は 0 が戻る.

【Коди помилок】

EX_ADR      : адреса пам'яті(lnk)のアクセスは許されていない. 
EX_DATA     : Файл (File)はデータФайл (File)ではない. 
EX_DFMT     : データ項目のデータ形式が不正である. 
EX_SDATA    : システムデータФайл (File)は存在しない.
dcls_dat
 
データボックスのクローズ

【Синтаксис / Прототип】

ERR dcls_dat(W fid)

【Параметри】

W   fid データボックスФайл (File)ID

【Значення, що повертається】

>= 0     Успішне виконання終了
＜0    код помилки

【Детальний опис】

fid で指定したオープン済みのФайл (File)をクローズして, そのФайл (File)に含まれるデータボックスの参照を終了する. これにより, データマネージャで使用していた管理用データ領域, 参照データ項目の領域等が解放される.

fid = 0 の場合は, システムデータボックスを含むすべてのオープン済みのФайл (File)をクローズする事を意味し, Процес (Process)の終了時には, 基本的に fid = 0 として dcls_dat() を行なう必要がある.

Процес (Process)が終了した場合は, 自動的にオープンしたФайл (File)はクローズされるが, dcls_dat() を明示的に行なうことが望ましい.

【Коди помилок】

EX_FD   : データФайл (File)IDが不正である.
dget_dtp
 
データ項目の参照

【Синтаксис / Прототип】

ERR dget_dtp(W type, W dnum, void **datap)

【Параметри】

W       type    データタイプ
W       dnum    データ番号
void    **datap データадреса пам'яті格納用

【Значення, що повертається】

>= 0     Успішне виконання終了
＜0    код помилки

【Детальний опис】

type で指定したデータタイプIDを持つ, dnum で指定したデータ番号のデータ項目を共有Оперативна пам'ять (Memory)上で参照できるようにして, そのадреса пам'ятіを *datap に戻す.

データ項目は, 最後にオープンしたデータボックスから, オープンされた逆順にサーチされ, システムデータボックスが最後にサーチされる. サーチの結果, 最初に見付かったデータ項目が対象となる.

【Коди помилок】

EX_ADR  : адреса пам'яті(datap)のアクセスは許されていない. 
EX_DFMT : データ項目のデータ形式が不正である. 
EX_DNUM : データ(type, dnum)はデータマネージャに登録されていない. 
EX_PAR  : параметриが不正である.
dget_siz
 
データ項目のрозмір у байтах取出し

【Синтаксис / Прототип】

W   dget_siz(B *addr)

【Параметри】

B   *addr   データボックスデータのадреса пам'яті

【Значення, що повертається】

>= 0     Успішне виконання終了(関数値はデータ項目のバイトрозмір у байтах)
＜0    код помилки

【Детальний опис】

addr で指定した共有Оперативна пам'ять (Memory)上のデータ項目のバイトрозмір у байтахを関数値として戻す.

【Коди помилок】

EX_AKEY : データ項目のадреса пам'ятіが不正である.
dget_num
 
データ番号／タイプIDの取出し

【Синтаксис / Прототип】

W   dget_num(B *addr, W *type)

【Параметри】

B   *addr   データボックスデータのадреса пам'яті
W   *type   データタイプIDの格納場所

【Значення, що повертається】

>= 0     Успішне виконання終了(関数値はデータ番号)
＜0    код помилки

【Детальний опис】

addr で指定した共有Оперативна пам'ять (Memory)上のデータ項目のデータ番号を関数値として戻し, データタイプIDを type で指定した領域に格納する. type = NULL の時は, データタイプIDは格納されない.

【Коди помилок】

EX_ADR  : адреса пам'яті(type)のアクセスは許されていない.

ddef_dat
 
システムデータ項目の再定義

【Синтаксис / Прототип】

ERR ddef_dat(W type, W dnum, void *ptr, W size)

【Параметри】

W       type    データタイプ
W       dnum    データ番号
void    *ptr    データадреса пам'яті
W       size    データのバイト数

【Значення, що повертається】

>= 0     Успішне виконання終了
＜0    код помилки

【Детальний опис】

ptr で指定した領域にある size バイトのデータを, type で指定したデータタイプID, dnum で指定したデータ番号を持つすでに存在するシステムデータ項目と置き換える.

この関数により再定義したデータ項目は, 一時的な登録であって, Файл (File)に格納されないため, 解放した場合には, 再度定義し直さない限り参照できなくなる.

【Коди помилок】

EX_ADR  : адреса пам'яті(ptr)のアクセスは許されていない. 
EX_DFMT : データ項目のデータ形式が不正である. 
EX_DNUM : データ(type, dnum)はデータマネージャに登録されていない. 
EX_PAR  : параметриが不正である.
ddef_ldt
 
ローカルデータ項目の登録

【Синтаксис / Прототип】

ERR ddef_ldt(W type, W dnum, void *ptr, W size)

【Параметри】

W       type    データタイプ
W       dnum    データ番号
void    *ptr    データадреса пам'яті
W       size    データのバイト数

【Значення, що повертається】

>= 0     Успішне виконання終了
＜0    код помилки

【Детальний опис】

ptr で指定した領域にある size バイトのデータを, type で指定したデータタイプID, dnum で指定したデータ番号を持つローカルデータ項目として登録する.

登録したデータ項目は, そのПроцес (Process)からのみ参照可能であり, 最後にオープンしたデータボックスとして取り扱われるため, 常に最初にサーチされる.

この関数により登録したデータ項目は, 一時的な登録であって, Файл (File)に格納されないため, 解放した場合には, 再度登録し直さない限り参照できなくなる.

【Коди помилок】

EX_ADR  : адреса пам'яті(ptr)のアクセスは許されていない. 
EX_DFMT : データ項目のデータ形式が不正である. 
EX_PAR  : параметриが不正である.
