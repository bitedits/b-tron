1.8 Пристрій (Device)管理

1.8.1 Пристрій (Device)管理функціонал / підсистемаの概要

Пристрій (Device)管理функціонал / підсистемаでは, прикладний додаток / програмаが各種のПристрій (Device)を統一的に取り扱うためのインタフェースфункціонал / підсистема, および各種のПристрій (Device)に対応したПристрій (Device)ドライバの登録／管理функціонал / підсистема, Пристрій (Device)ドライバとのインタフェースфункціонал / підсистемаを提供している. ここでは, прикладний додаток / програмаインタフェースのみについて記述する.

また, OS 核のФайл (File)管理функціонал / підсистемаやПодія (Event)管理функціонал / підсистемаでは, 内部的にПристрій (Device)管理функціонал / підсистемаを経由して実際のПристрій (Device)操作を行なうことになる.

以下にПристрій (Device)管理функціонал / підсистемаの位置付けを示す.

図 14 : Пристрій (Device)管理функціонал / підсистемаの位置付け

使用されるПристрій (Device)としては以下のようなものがある.

  1. ビットマップディスプレイ (CRT, LCD, 等)
  2. Клавіатура (Keyboard) (KD)
  3. Вказівний пристрій (Pointing Device) (PD)
  4. 各種ディスク装置 (FD, HD, OD, CD-ROM, 等)
  5. 各種のプリンタ
  6. 通信回線 (RS-232C, モデム, 各種ネットワーク, 等)
  7. スピーカ
  8. イメージ処理装置
  9. その他

これらのПристрій (Device)のうち, ビットマップディスプレイに対するприкладний додаток / програмаインタフェースは, Пристрій (Device)管理функціонал / підсистемаとは独立したディスプレイ関数群として提供される.

これらのディスプレイ関数群は通常ドライバと一体となっているためドライバインタフェースも適用されないことになり, Пристрій (Device)管理функціонал / підсистемаとは基本的に独立した存在となる.

また, Клавіатура (Keyboard)とВказівний пристрій (Pointing Device)に対するприкладний додаток / програмаインタフェースはПодія (Event)管理функціонал / підсистемаとして提供されるが, ドライバとのインタフェースはПристрій (Device)管理でサポートしている.

各種のディスク装置の場合は, 通常はФайл (File)として使用されるが, Пристрій (Device)として直接取り扱うためのприкладний додаток / програмаインタフェースも用意される.

1.8.2 Пристрій (Device)

Пристрій (Device)のタイプ

Пристрій (Device)は文字型Пристрій (Device)とブロック型Пристрій (Device)の 2 種類に分類される. 文字型Пристрій (Device)は基本的にバイト単位でデータの入出力をシーケンシャルに行なうもので, ブロックПристрій (Device)はПристрій (Device)毎に定められた大きさのデータブロック単位での入出力を行なうものでブロック単位でのランダムなアクセスが可能である.

各種のディスク装置はブロック型Пристрій (Device)であり, その他のほとんどのПристрій (Device)は文字型Пристрій (Device)となる.

また, Пристрій (Device)は実Пристрій (Device)と仮想Пристрій (Device)に分類される. 実Пристрій (Device)は物理的に実際に存在する通常の意味でのПристрій (Device)であり, 仮想Пристрій (Device)はある種の資源を仮想的に 1 つのПристрій (Device)として取り扱うものである. 仮想Пристрій (Device)の代表的なものとしては画面上の 1 つのウィンドウを仮想的に1つのコンソールとして取り扱う仮想コンソールがあげられる.

論理Пристрій (Device)名

Пристрій (Device)は, 論理Пристрій (Device)名と呼ばれるユニークな文字列によりシステムに登録され, 識別される. 論理Пристрій (Device)名は, 基本的に以下に示す 3 つの要素から構成される.

種別:
Пристрій (Device)の種類を表わす名称であり, "hd"(ハードディスク), "fd"(フロッピーディスク)等がある.
ユニット:
同一種別のПристрій (Device)が複数個存在する場合に, 個々のПристрій (Device)を識別するために使用され, 通常, "a" 〜 の英文字1文字が使用される.
サブユニット:
1つのユニットを論理的に複数に分割した場合に, 個 々の分割単位を識別するために使用され, "0"〜"254"の最大3桁の連続した数字で表わされる.

種別 + ユニット を, 特にユニット名と呼び, OS で識別される単位となる. OS 側では種別とユニットの区別は認識せず, 両方を合わせた名称であるユニット名により, Пристрій (Device)を識別する. ユニット名の最後の文字は数字であってはいけない.

論理Пристрій (Device)名は, «ユニット名＋サブユニット番号»で表わされ, 全体として最大 8 文字 ( 16 バイト ) の文字列となる. サブユニット番号は前に 0 の付かない 3 桁までの数字である. サブユニットが存在しない場合, ユニット名がそのまま論理Пристрій (Device)名と成り得る. 論理Пристрій (Device)名の最後の文字が数字である場合は, その論理Пристрій (Device)名はサブユニットを表わしているものと見なされる. サブユニット全体を表わす場合, サブユニット番号は付けず, ユニット名そのものが論理Пристрій (Device)名となる.

サブユニット ( パーティション ) を表わすために最大 3 桁の数字 ( サブユニット番号 ) が使用されるが, サブユニットの分割を無視した 1 つのユニットとして取り扱う場合は, サブユニット番号を含めない論理Пристрій (Device)名 ( ユニット名 ) を使用する. これは, 主にサブユニットの分割 (即ち, ディスクのパーティショニング ) を行なうために使用される. なお, サブユニット番号を含まない論理Пристрій (Device)名 ( ユニット名 ) を特に物理Пристрій (Device)名と呼ぶ.

図 15 : 論理Пристрій (Device)名

Пристрій (Device)の登録は, 実際には対応するПристрій (Device)ドライバの登録を意味し, Пристрій (Device)ドライバはユニット単位でユニット名により定義される. 即ち, 1 つのユニットに含まれるすべてのサブユニットは 1 つのПристрій (Device)ドライバで処理される. 通常, Пристрій (Device)ドライバはПристрій (Device)の種別に対応して用意され, 1 つのПристрій (Device)ドライバで複数のユニットを処理する場合が多いが, 複数のユニットを複数のПристрій (Device)ドライバで処理してもよい.

なお, 今後単にПристрій (Device)名と言った場合は, 論理Пристрій (Device)名を意味するものとする.

Пристрій (Device)のアクセス制御

ディスク等のПристрій (Device)では, システムの安全性を保つために, そのПристрій (Device)を使用できるユーザを制限することが望ましい. このため, Процес (Process)のユーザレベルによるПристрій (Device)のアクセス制御が行なわれる.

各Пристрій (Device)には以下に示す 1 ワードのアクセスモードが保持されており, これによりПристрій (Device)のアクセス権がチェックされる ( これはФайл (File)に於ける一般アクセスレベルに相当するものである ).

図 16 : Пристрій (Device)のアクセスモード

即ち, 読込可能なユーザレベルを持つПроцес (Process)からのみПристрій (Device)の読込用 ( D_READ) のオープンが可能で, 書込可能なユーザレベルを持つПроцес (Process)からのみПристрій (Device)の書込用 ( D_WRITE ) のオープンが可能となる. また, アクセス可能なユーザレベルを持つПроцес (Process)からのみ, そのПристрій (Device)をФайл (File)システムとして取り扱うことが可能であり, Файл (File)システムの接続 / 切断 / 管理情報読込みのФайл (File)管理のсистемний виклик (System Call)を実行できる.

Пристрій (Device)のアクセスモードは, Пристрій (Device)の登録時に R = W = F = 15 に設定される. 登録後はユーザレベル 0 のПроцес (Process)からのみ変更可能となる.

1.8.4 системний виклик (System Call)

opn_dev
 
Пристрій (Device)のオープン

【Синтаксис / Прототип】

WERR    opn_dev(TC* dev, W o_mode, W* error)

【Параметри】

TC* dev       対象Пристрій (Device)名

W   o_mode    オープンモード
    ( D_READ ‖ D_WRITE ‖ D_UPDATE ) | [ D_EXCL ‖ D_WEXCL ]
                            | [ D_NOWAIT ]
    D_READ    読み込み用オープン(Rアクセス権が必要)
    D_WRITE   書き込み用オープン(Wアクセス権が必要)
    D_UPDATE  更新(読み込み／書き込み)用オープン(RWアクセス権が必要)
    D_EXCL    排他モード
    D_WEXCL   排他書き込みモード
    D_NOWAIT  待ち無し指定
              文字型Пристрій (Device)の場合, オープン時にПристрій (Device)がレディ状態になる
              まで待たずにリターンする. この指定でオープンした場合は, 
              rea_dev(), wri_dev() で入力データが得られなかったり, 出力が
              ビジー状態の場合には, 待たずにリターンする. 

W*  error     詳細Помилка情報格納領域
              *error には, Пристрій (Device)ドライバから戻されたПомилка情報が設定される. 
              Помилка情報の内容は, 各Пристрій (Device)ドライバによって異なる. 
              error が NULL の場合, Помилка情報は格納しない.

【Значення, що повертається】

＞0    Успішне виконання(Пристрій (Device)ディスクリプタ)
＜0    код помилки

【Детальний опис】

指定したПристрій (Device)を指定したモードでオープンする. Пристрій (Device)をオープンするためにはオープンモードに対応するアクセス権が必要である.
排他モード, および排他書込モードはФайл (File)に対するものと全く同様のфункціонал / підсистемаであり, 1つのПристрій (Device)の同時オープンを制限することになる. なお, 物理Пристрій (Device)名によるオープンは, 対象とするユニットのすべての論理Пристрій (Device) に対するオープンを同時に行なったものとみなされた排他制御が行なわれる. 例えば, "hda" の D_EXCL オープンは, "hda#" が1つもオープンされていない場合のみ可能であり, 逆に "hda" をD_EXCL オープンした後は, どの "hda#" のオープンも不可となる.

【Коди помилок】

ER_ACCES    : Пристрій (Device)(dev)のアクセス権(R,W)がない. 
ER_ADR      : адреса пам'яті(dev,error)のアクセスは許されていない. 
ER_BUSY     : Пристрій (Device)(dev)は既に排他的にオープンされている為, 
              同時にПристрій (Device)をオープンすることができない, 
              またはФайл (File)システムとして接続されている. 
ER_DEV      : Пристрій (Device)(dev)に対しての読込みまたは書込み操作は許されていない. 
ER_ERDEV    : 装置異常が発生した. 
ER_IO       : 入出力Помилкаが発生した. 
ER_LIMIT    : 同時オープン可能な最大Пристрій (Device)数を越えた. 
ER_MINTR    : Повідомлення (Message)ハンドラが起動されたため, 処理が中断された. 
ER_NODEV    : Пристрій (Device)(dev)へのアクセスができない. 
ER_NOEXS    : Пристрій (Device)(dev)は存在していない(登録されていない). 
ER_NOMDA    : Пристрій (Device)(dev)のメディアが存在しない. 
ER_NOSPC    : システムのОперативна пам'ять (Memory)領域が不足した. 
ER_PAR      : параметриが不正である(o_modeが不正). 
ER_RONLY    : Пристрій (Device)(dev)は書込不可である.

Пристрій (Device)のデータ読み込み

            固有データ   単位はПристрій (Device)依存
            属性データ   単位はバイト

W*  a_size  読み込んだデータрозмір у байтах
            固有データ   単位はПристрій (Device)依存
            属性データ   単位はバイト

W*  error   詳細Помилка情報格納領域
            *error には, Пристрій (Device)ドライバから戻されたПомилка情報が設定される. 
            Помилка情報の内容は, 各Пристрій (Device)ドライバによって異なる. 
            error が NULL の場合, Помилка情報は格納しない.

【Значення, що повертається】

= 0    Успішне виконання

＜0    код помилки

【Детальний опис】

オープンしたПристрій (Device)のデータを指定した開始データ番号から指定したрозмір у байтахだけ読み込む.
size = 0 の時は実際の読み込みは行わずに, a_size に読み込み可能なデータрозмір у байтахを戻す.
文字型Пристрій (Device)の場合は, オープン時の指定により以下に示す動作となる(詳細は個々のПристрій (Device)に依存する).
D_NOWAIT 指定の時:
その時点で得られたバイト数(size で指定したバイト数以下)のデータだ けを読み込む. 何もデータが無い場合は, *a_size に０がセットされ, ER_BUSY のПомилкаとなる.
D_NOWAIT 指定でない時:
size で指定したバイト数のデータが得られるか, データが終了となるま で待つ.

            属性データ   単位はバイト

W*  error   詳細Помилка情報格納領域
            *error には, Пристрій (Device)ドライバから戻されたПомилка情報が設定される. 
            Помилка情報の内容は, 各Пристрій (Device)ドライバによって異なる. 
            error が NULL の場合, Помилка情報は格納しない.

【Значення, що повертається】

= 0      Успішне виконання
＜0   код помилки

【Детальний опис】

オープンしたПристрій (Device)へ指定した開始データ番号から指定したрозмір у байтахだけデータを書き込む.
size = 0 の時は実際の書き込みは行わずに, a_size に書き込み可能なデータрозмір у байтахを戻す.
文字型Пристрій (Device)の場合は, オープン時の指定により以下に示す動作となる(詳細は個々 のПристрій (Device)に依存する).
D_NOWAIT 指定の時:
その時点で得られたバイト数(size で指定したバイト数以下)のデータだ けを読み込む. 何もデータが無い場合は, *a_size に０がセットされ, ER_BUSY のПомилкаとなる.
D_NOWAIT 指定でない時:
size で指定したバイト数のデータが得られるか, データが終了となるま で待つ.

【Коди помилок】

ER_ADR      : адреса пам'яті(buf,a_size,error)のアクセスは許されていない. 
ER_BUSY     : データは書き込めなかった(D_NOWAITオープン時). 
ER_DD       : Пристрій (Device)ディスクリプタは存在していない, 
              または D_READ オープンである. 
ER_DEV      : Пристрій (Device)(dev)に対しての書込み操作は許されていない. 
ER_ERDEV    : 装置異常が発生した. 
ER_IO       : 入出力Помилкаが発生した. 
ER_MINTR    : Повідомлення (Message)ハンドラが起動されたため, 処理が中断された. 
ER_NODEV    : Пристрій (Device)(dd)へのアクセスができない. 
ER_NOMDA    : Пристрій (Device)(dd)のメディアが存在しない. 
ER_PAR      : параметриが不正である(size< 0,start不正). 
ER_RONLY    : Пристрій (Device)(dev)は書込不可である.

sus_dev


 


サスペンド要求





【Синтаксис / Прототип】


WERR    sus_dev(UW mode)




【Параметри】


mode ::＝ ( D_SUSPEND ‖ D_DISSUS ‖ D_ENASUS ‖ D_CHECK ) | [D_FORCE]

    D_SUSPEND   0x0001  サスペンドする
    D_DISSUS    0x0002  サスペンドを禁止する
    D_ENASUS    0x0003  サスペンドを許可する
    D_CHECK     0x0004  サスペンド禁止カウントを調べる
    D_FORCE     0x8000  強制サスペンド指定



【Значення, що повертається】

>= 0     Успішне виконання (D_CHECK のときはサスペンド禁止要求カウント数)

＜0    код помилки


【Детальний опис】

システムのサスペンドの制御を行う. 


 
D_SUSPEND
 
サスペンドおよび強制サスペンド許可状態なら, サスペンドを行う. サスペンド状態から復帰(リジューム)すると, системний виклик (System Call)からリターンする. 
 
D_DISSUS
 
サスペンドを禁止する. 
 
D_ENASUS
 
サスペンドを許可する. 
        D_DISSUS の要求回数はカウントされ, 同じ回数だけ D_ENASUS を要求して初めてサスペンドが許可される. 

        初期状態は, サスペンド許可である. 
 
D_CHECK
 
現在のサスペンド禁止要求カウント数を調べ, リターン値に返す. ０ならサスペンド許可状態である. 
     

    D_FORCE が指定されると, 強制サスペンドに関する操作となる. 

 
D_FORCE|D_SUSPEND
 
強制サスペンド許可状態なら, サスペンドを行う. D_DISSUS による通常のサスペンド禁止は無視される. 
 
D_FORCE|D_DISSUS
 
強制サスペンドを禁止する. 
 
D_FORCE|D_ENASUS
 
強制サスペンドを許可する. 

 D_FORCE|D_DISSUS の要求回数はカウントされ, 同じ回数だけ D_FORCE|D_ENASUS を
     要求して初めて強制サスペンドが許可される. 
     初期状態は, 強制サスペンド許可である. 
 
D_FORCE|D_CHECK
     現在の強制サスペンド禁止要求カウント数を調べ, リターン値に返す. ０なら強制サスペンド許可状態である. 



    サスペンドおよび強制サスペンドを禁止したПроцес (Process)が終了すると, そのПроцес (Process)が行った禁止要求は解除される. 


【Коди помилок】


ER_BUSY     : サスペンド禁止状態のためサスペンドできなかった. 
ER_PAR      : параметриが不正である. 
ER_LIMIT    : サスペンド禁止要求カウントがシステムの制限を超えた. 
ER_MINTR    : Повідомлення (Message)ハンドラが起動されたため, 処理が中断された.
