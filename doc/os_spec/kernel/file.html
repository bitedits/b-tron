1.6 Файлова система та менеджер файлів (File Management)

1.6.1 Огляд підсистеми управління файлами

概要

Підсистема управління файлами BTRON визначає логічну структуру файлової системи на носіях (FD, HD, Flash) та надає повний набір системних викликів для роботи з файлами, записами та посиланнями.

Фізична та внутрішня структура даних файлової системи оптимізована для високої швидкодії. Для змінних носіїв (дискет тощо) фізичний формат стандартизований специфікацією BTRON для забезпечення 100% сумісності.

Файлова система побудована на базі концепції Реальних об'єктів (Real Objects / Реальний об'єкт (Real Object)) та Віртуальних посилань (Virtual Objects / Віртуальний об'єкт (Virtual Object)):

  • Організація файлів у вигляді послідовності записів змінної довжини (Record Stream)
  • Мережева граф-структура зв'язків за допомогою посилань (Virtual Objects) без традиційної концепції каталогів/директорій
  • Прямий доступ до файлів (Реальних об'єктів) через унікальні деスクリプтори посилань
  • Багаторівнева система захисту прав доступу на основі ідентифікаторів користувачів та груп

Оскільки файли можуть використовуватися кількома користувачами одночасно у мережевому середовищі, система забезпечує гнучкий багаторівневий контроль доступу та високий ступінь захисту даних.

Файли (Реальні об'єкти) та Посилання (Віртуальні об'єкти)

Файл (Реальний об'єкт / Real Object) є контейнером даних і складається з впорядкованої послідовності записів (Records) змінної довжини.

Посилання (Віртуальний об'єкт / Virtual Object) — це прямий системний покажчик на Реальний об'єкт, що містить ідентифікатор цільового файла та додаткові візуальні й функціональні атрибути.

Посилання зберігається у вигляді спеціального запису (Link Record) всередині будь-якого файла. На один Реальний об'єкт може вказувати необмежена кількість Віртуальних посилань у різних файлах.

У графічному середовищі BTRON Віртуальний об'єкт (Віртуальний об'єкт (Virtual Object)) відображається у вигляді іконки/вузла, відкриття якого надає прямий доступ до вмісту Реального об'єкта (Реальний об'єкт (Real Object)).

Адресація файлів виконується безпосередньо через посилання (дескриптори), тому ім'я файла не є унікальним шляхом. Ім'я файла містить до 20 символів TRON Code і може дублюватися.

Файл (File)システム

Файл (File)システムはФайл (File)を管理するための 1 つの物理的な単位であり, 1つの機器上の以下のような記憶媒体上に構築され, 物理的なрозмір у байтахの上限を持つ.

  • フロッピーディスク
  • ハードディスク ( の 1 つのパーティション )

Файл (File)システムには, 必ず 1 つのルートФайл (File)が存在し, そのルートФайл (File)に含まれるПосилання (Link)を順次たどっていくことにより, そのФайл (File)システム内の全てのФайл (File)に基本的に到達可能である. ルートФайл (File)は, Реальний об'єкт (Real Object) / Віртуальний об'єкт (Virtual Object)モデルとの対応においてПристрій (Device)Реальний об'єкт (Real Object)に対応する.

Файл (File)間のПосилання (Link)による参照関係は, 基本的に 1 つのФайл (File)システム内で定義され整合が取られるが, 他のФайл (File)システムに存在するФайл (File)を参照するための間接的なПосилання (Link)を持つことができ, これを特に間接Посилання (Link)と呼ぶ. 間接Посилання (Link)による参照の場合は, 参照先の他のФайл (File)システムの変更に対する整合は取られないため, 参照先のФайл (File)の存在は保証されない場合があるため注意が必要である.

Файл (File)システムの生成時には, Файл (File)システム名, およびПристрій (Device)所在名が設定される.

Файл (File)システム名はルートФайл (File)の名称としても設定される最大 20 文字の名前であり, システムおよびユーザがФайл (File)システムを絶対的に識別するために使用される. Файл (File)システム名が同一のФайл (File)システムは, 同一とみなされるため, Файл (File)システム名はユニークでなければいけない.

Пристрій (Device)所在名は, Файл (File)システムが格納されている物理Пристрій (Device)を示す最大20文字の名前であり, ネットワーク経由で他のマシンをアクセスする場合や, フロッピー等の装着を求める場合に使用される. 通常, Пристрій (Device)所在名としてはハードディスク等の機器に固定的に付属しているПристрій (Device)の場合にはその媒体の一般名称 ( 即ち«ハードディスク»等 ) が使用され, フロッピーディスク等の取り外し可能な媒体の場合にはその媒体の一般名称 ( 即ち«フロッピーディスク»等 ) が使用される.

Файл (File)システムの接続

システムのスタートアップ時には, Файл (File)システムは 1 つも存在していない状態であり, 接続操作を行なうことにより初めて, Файл (File)システムとして使用することが可能となる. 従って, 通常はシステムの初期化処理として最低限のФайл (File)システムの接続を行なう必要がある.

Файл (File)システムの接続は, 接続するФайл (File)システムが存在する論理Пристрій (Device)名と, 接続名を指定して行なわれる. 接続名は接続したФайл (File)システムを識別するための最大 8 文字の名前であり, 接続したФайл (File)システムのルートФайл (File)を示す絶対パス名称として使用される. また, 接続時には接続したФайл (File)システムのルートФайл (File)へのПосилання (Link)が得られる.

従って, 接続時に得られたПосилання (Link), または接続名を使用することにより, 接続したФайл (File)システム上のルートФайл (File)をアクセスすることが可能となり, ルートФайл (File)から順次Посилання (Link)をたどることにより, 接続したФайл (File)システム上の任意のФайл (File)をアクセスすることが可能となる.

Файл (File)システムの切断は, 切断するФайл (File)システムの論理Пристрій (Device)名を指定して行なわれ, これにより切断したФайл (File)システム上のФайл (File)を示すПосилання (Link)を通したФайл (File)のアクセスはできない状態となり, この状態を切断状態と呼ぶ.

Реальний об'єкт (Real Object) / Віртуальний об'єкт (Virtual Object)モデルとの対応において, 切断状態のПосилання (Link)は虚身に対応することになる.

Файл (File)システムの接続は, 単にФайл (File)システムの存在をФайл (File)管理функціонал / підсистемаに動的に登録するだけのфункціонал / підсистемаであり, 構造を持たない平坦な接続である. 従って, 複数のФайл (File)システムをまたがるネットワーク状の静的なФайл (File)参照構造は, 異なるФайл (File)システム上のФайл (File)を参照する間接Посилання (Link)を利用して構築することになる.

Файл (File)ID

1 つのФайл (File)システム内の全てのФайл (File)には, 生成時にФайл (File)IDと呼ばれるユニークな番号が付けられ, 内部的に識別される. Файл (File)IDは 0 〜 ( 最大Файл (File)ID ) の範囲の値であり, 最大Файл (File)ID(即ち, 最大のФайл (File)数)はФайл (File)システムの生成時に規定される. Файл (File)IDは 16 ビットの数値で表わされるため, 最大Файл (File)IDは 65535 を越えることはできない.

Посилання (Link)

Посилання (Link)は, Файл (File)をアクセスするための手掛かりとなる一種のвказівник (Pointer)であり, 参照するФайл (File)が存在するФайл (File)システム名, Файл (File)ID , およびПосилання (Link)としてのいくつかの属性データを保持しているデータ構造である.

Посилання (Link)は, ビジュアルな操作環境では, Віртуальний об'єкт (Virtual Object)として表示される.

Посилання (Link)は単なるвказівник (Pointer)としての動的なデータであるが, Файл (File)内に 1 つのЗапис (Record)として格納することにより固定的な存在となる. このように格納されたПосилання (Link)を特に固定 ( フィックスド ) Посилання (Link)と呼ぶ. 固定Посилання (Link)はФайл (File)システム名を持たないため, 同一のФайл (File)システム内のФайл (File)の参照のみ可能であり, Файл (File)から固定Посилання (Link)を取り出した時点で, そのФайл (File)の属するФайл (File)システム名がПосилання (Link)のデータ構造として設定されることになる.

このため, 異なるФайл (File)システムを参照するПосилання (Link)を固定Посилання (Link)としてФайл (File)内に格納する場合は, あらかじめ, 格納するФайл (File)システム内にПосилання (Link)Файл (File)と呼ばれる特殊なФайл (File)を生成し, そのПосилання (Link)Файл (File)を示すПосилання (Link)を固定Посилання (Link)として格納する必要がある.

Посилання (Link)Файл (File)は, 参照するФайл (File)の存在するФайл (File)システム名, Файл (File)ID, Файл (File)名, および生成日時 を保持している特殊なФайл (File)であり, Посилання (Link)Файл (File)へのアクセスは, 参照している異なるФайл (File)システム内のФайл (File)へのアクセスと自動的に解釈される. Посилання (Link)Файл (File)を示すПосилання (Link)を特に間接Посилання (Link)と呼び, 通常のФайл (File)を示すПосилання (Link)を直接Посилання (Link)と呼ぶ.

多重の間接Посилання (Link), 即ち 2 つ以上のПосилання (Link)Файл (File)を経由したФайл (File)の参照はサポートされないため, アクセスした時点でФайл (File)は存在しないというПомилкаになる.

間接Посилання (Link)によるПосилання (Link)Файл (File)経由によるФайл (File)の参照は, 以下のように行なわれる.

  • Файл (File)システム名によりФайл (File)システムを特定する. 接続されていない場合は, アクセスは不可となる. なお, 接続名は, Посилання (Link)Файл (File)経由のアクセスには無関係である.

  • Файл (File)IDにより特定したФайл (File)システム内のФайл (File)をチェックし, Файл (File)名および生成日時の両方またはどちらか一方が一致しており, かつそのФайл (File)がПосилання (Link)Файл (File)でない場合に, そのФайл (File)を対象としてアクセスを行なう.
    それ以外の場合は, 参照すべきФайл (File)が存在しなくなったものとみなしてア クセスは不可となる.

Файл (File)には, 大きく以下の2種類のタイプが存在し, 単にФайл (File)と言った場合は, 通常Файл (File)を意味する.

  • Запис (Record)розмір у байтах

Запис (Record)タイプは, Запис (Record)のタイプを示す 0 〜 31 の値である.

1.6.4 Права доступу та захист файлів (Access Control & Security)

Файл (File)のアクセス管理

Файл (File)のアクセス管理はФайл (File)をアクセスできるユーザを特定, または制限することにより, Файл (File)の機密保護や不慮の改変／削除から保護するための機構であり, Файл (File)をアクセスするПроцес (Process)が持つユーザ情報と, 各Файл (File)に設定されたアクセス管理情報を照らし合わせることによりФайл (File)アクセスの可否を決定することになる.

ユーザ情報

各ユーザには, 以下に示すユーザ情報が設定される.

  • ユーザ名 (12文字) + 隠しユーザ名 (2文字)
  • 所属グループ名1 (12文字) + 隠しグループ名1 (2文字)
  • 所属グループ名2 (12文字) + 隠しグループ名2 (2文字)
  • 所属グループ名3 (12文字) + 隠しグループ名3 (2文字)
  • 所属グループ名4 (12文字) + 隠しグループ名4 (2文字)
  • ユーザレベル (0〜15, 0が最高レベル)
  • ネットワークユーザレベル (1〜15, 1が最高レベル)

隠しユーザ名, 隠しグループ名は, 英数字 4 文字程度を暗号化して, 2 文字にコード化したものであり, ユーザ名, グループ名と合わせて, それぞれ 14 文字の名前として使用される. 隠し名は同一名の衝突を避けるとともに, 暗証コードとしての役割を持っている.

隠し名の暗号化アルゴリズムはインプリメントに依存した非公開のものであり, また個々の機器毎に異なる暗号化がされる必要がある.

これらのユーザ情報はシステム動作開始時に使用者のデフォールト値から読み込まれ, 初期Процес (Process)のユーザ情報となる. このユーザ情報は子Процес (Process)に継承され, そのПроцес (Process)がФайл (File)をアクセスする際のユーザ情報として使用される.

Файл (File)のアクセス管理情報

各Файл (File)には以下のアクセス管理情報が設定される.

  • Файл (File)の所有者名(12文字) + 隠し名 (2文字)
  • Файл (File)の所有グループ名 (12文字) + 隠し名 (2文字)
  • Файл (File)のアクセスモード
    • 所有者アクセスモード :
      Файл (File)の所有者に対しての RWE それぞれの可否
    • グループアクセスレベル :
      Файл (File)の所有グループに所属する各ユーザに対して, RWE それぞれが許可されている最低ユーザレベル (0〜15) の指定
    • 一般アクセスレベル :
      一般のユーザに対して RWE それぞれが許可されている最低ユーザレベル ( 0〜15 ) の指定
  • Файл (File)のアクセス属性
    • 書込不可属性
    • 削除不可属性

アクセスモードの, RWE は以下の意味を持つ. 

    R -- Файл (File)の読出しの可否
    W -- Файл (File)への書込み / 変更の可否
    E -- Файл (File)の実行またはФайл (File)内のПосилання (Link)の検索の可否

Файл (File)の所有者名は, そのФайл (File)を生成したユーザ名が自動的に設定され, 生成した後は一切変更することはできない. また, グループ名, アクセスモードは, Файл (File)の生成時に指定することができる. グループ名は, そのユーザが所属する最大 4 つのグループのなかの 1 つを指定することになる.

即ち, Файл (File)の生成時には, 以下のものを指定することができる.

  • 所有者の RWE それぞれの可否
  • グループの RWE それぞれの許可最低レベル (0〜15)
  • 一般の RWE それぞれの許可最低レベル (0〜15)
  • 自分の所属グループの内でどれをФайл (File)の所有グループとするかの指定
    ( 0はグループなし, 1〜4は自分の所属グループのどれを設定するかを示す)

ユーザ毎にデフォールトアクセスモードが定義されており, Файл (File)の生成時にデフォールトとして適用させることができる. このデフォールトアクセスモードはユーザー固有の情報として格納されている内容が使用されるが, 実行時に変更することも可能である. 変更した内容はそのユーザの全Процес (Process)に対して有効となる.

また, Файл (File)の所有者名, グループ名の最初の 1 バイトが 0 の場合は, 所有者またはグループが存在しないことを意味し, その場合は所有者アクセスモード, グループアクセスレベルは誰にも適用されないことになる.

Файл (File)に設定されたアクセス管理情報は, その所有者のみが変更できる (ただし, 所有者名は一切変更できない) . 所有者がないФайл (File)の場合は, 例外的にレベル 0 のユーザーであればアクセス管理情報を変更することができる.

書込不可属性は, Файл (File)の内容の変更を禁止する属性であり, この属性が ON の状態ではすべての変更操作は所有者を含めた全てのユーザに対して禁止される.

削除不可属性は, Файл (File)の削除を禁止する属性であり, この属性が ON の状態では, Файл (File)の削除は所有者を含めた全てのユーザに対して禁止される.

削除不可属性が設定されていないФайл (File)の削除は, 特にアクセス権を必要としないが, Файл (File)はどこからも参照されていない場合にのみ削除可能であるため, 実際には削除すべきФайл (File)への固定Посилання (Link)を含むすべてのФайл (File)の書込みアクセス権がない限り削除できないことになる.

なお, Файл (File)システムの接続操作においては, 書込不可の接続指定が可能であり, この場合はそのФайл (File)システムに対するいかなる変更操作も禁止される. 同様に物理的に«書き込み不可»となっているフロッピーディスク等の場合も, いかなる変更操作も禁止される.

Файл (File)のアクセスチェック

Файл (File)のアクセスチェックは, そのユーザが所有者であれば, 所有者アクセスモード, グループに所属していればグループアクセスレベル, その他の場合は一般アクセスレベルが適用される.

Файл (File)の所有者名, グループ名の隠し名が0の場合は, 隠し名のマッチングは行なわないものとする. 即ち, Процес (Process)のユーザ情報にある所有者名, グループ名のそれぞれ 12 文字のみのマッチングにより同一性を判断することになる.

レベル 0 のユーザは, 基本的にすべてのФайл (File)の RWE が可能 ( 書込不可属性が付けられた場合には W はできない) となるが, 所有者としての権利はないため, アクセスモード, アクセス属性等を変更することはできない. 

例：

    所有者 :                 佐藤
    所有グループ :           プロジェクトA
    所有者アクセスモード :   R W E 可能
    グループアクセスレベル : R レベル 13, W レベル 10, E レベル 13
    一般アクセスレベル :     R レベル  3, W レベル  1, E レベル  5

上記の例の場合, «プロジェクトA»に所属するレベル 0 〜 10 のユーザは, RWE 可能であり, レベル 11 〜 13 のユーザは, RE 可能で, レベル 14, 15 のユーザは一切のアクセスは禁止される.
また, «プロジェクトA»に属さないユーザに対しては, レベル 0, 1 は RWE 可能であり, レベル 2, 3 は RE 可能, レベル 4, 5 は 3 のみ可能, レベル 6 〜 15 は一切のアクセスが禁止される.

アクセス管理のレベル

フロッピーディスクは, 通常データの交換媒体として使用されることが多く, フロッピーディスク上のФайл (File)に対してはアクセス管理はない方が都合が良い場合が多い. ただし, 交換の相手を特定したい場合や, 共用的に使用する場合にはアクセス管理が有効な場合もある.

このために, Файл (File)システム単位で以下の 3 種類のアクセス管理のレベルを設定することができるようにする. このアクセス管理のレベルは, そのФайл (File)システム上のすべてのФайл (File)に対して適用され, Файл (File)を生成する場合, およびФайл (File)のアクセス管理情報を変更する場合に, 以下に示したルールに従ってアクセス管理情報の設定が行なわれる.

従って, Файл (File)の通常のアクセスチェックに関してはレベルの区別なく行なわれるが, 所有者のチェックに関しては, レベル0のФайл (File)システムは特別に取り扱われ, 誰でも所有者としての権利を持つことになる.

a. レベル 0 -- アクセス管理は一切行なわれない

常に以下の内容のアクセス管理情報が設定される. 

     所有者名, 隠し名       : 0 (なし)
     グループ名, 隠し名     : 0 (なし)
     所有者アスセス         : 0 (RWE不可)
     グループアクセスレベル : 0 (RWE不可)
     一般アクセスレベル     : 0x0fff (誰でもRWE可)
b. レベル 1 -- アクセス管理は部分的に行なわれる

所有者名/グループ名の隠し名は常に 0 に設定される.

c. レベル 2 -- アクセス管理は完全に行なわれる

完全なアクセス管理情報が設定される.

一般にフロッピーディスク等の取り外し可能媒体に対しては, レベル 0 またはレベル 1 とし, ハードディスク等の機器に固定的に付属するものに関してはレベル 2 とする. 取り外し可能媒体に対してレベル 2 を設定した場合は, 暗号化が機器毎に異なるため事実上 1 つの機器でしか使用できなくなる.

このアクセス管理レベルはФайл (File)システムを生成する時点で, Файл (File)システムの管理情報として設定される.

1.6.5 Операції над файлами та покажчики (File Operations)

Процес (Process)の環境

Файл (File)はПроцес (Process)によりアクセスされるが, オープンしたФайл (File)に対しては各Процес (Process)毎で定義されるФайл (File)ディスクリプタ (fd ＞ 0 ) という正の整数値が割り当てられ, そのФайл (File)ディスクリプタを使用して実際のФайл (File)アクセスを行なう.

Процес (Process)の終了時には, オープンしたФайл (File)はすべて自動的にクローズされる.

また, オープンしたФайл (File)に対しては, 現在対象としているЗапис (Record)を示す現在Запис (Record)が定義される.

Файл (File)ディスクリプタ, 現在Запис (Record)位置は, そのПроцес (Process)固有のものとして定義され, 子Процес (Process)には特に継承されない.

Процес (Process)の環境として作業Файл (File), ユーザ管理情報は子Процес (Process)に継承される. また, デフォールトアクセスモードはユーザ毎に定義され, 変更した場合は同一ユーザーのすべてのПроцес (Process)に対して即時に有効となる.

Файл (File)の参照カウント

Файл (File)には, そのФайл (File)を参照している同一Файл (File)システム内の固定Посилання (Link)の数を示す参照カウントが存在する. 参照カウントはФайл (File)を生成した時点では 0 であり, Файл (File)に対する固定Посилання (Link)を生成した時点, 即ち, Посилання (Link)をФайл (File)内に格納した時点で +1 される. 逆に固定Посилання (Link)が削除された時点で参照カウントは -1 される.

参照カウントは, 同一Файл (File)システム内での参照を示すため, Посилання (Link)Файл (File)を経由したФайл (File)の参照は, 参照カウントに反映されないことになる. なお, Посилання (Link)Файл (File)自体にも参照カウントは適用される.

Файл (File)の削除は参照カウント 0 のФайл (File)に対してのみ可能である. 削除したФайл (File)に固定Посилання (Link)が含まれていた場合は, その固定Посилання (Link)が参照しているФайл (File)の参照カウントが -1 されるが, その結果 0 となった場合でも, そのФайл (File)は削除されない. なお, 固定Посилання (Link)が含まれているФайл (File)の削除は, 削除時に強制削除の指定を行なった時のみ可能となる.

Посилання (Link)Файл (File)の削除も同様であり, Посилання (Link)Файл (File)自体の参照カウントが 0 の場合に削除可能となる. なお, Посилання (Link)Файл (File)の参照先のФайл (File)は, Посилання (Link)Файл (File)経由で削除することはできない.

Файл (File)システムのルートФайл (File)は例外的に参照カウントが最初から 1 となっており, 決して削除することができないようになっている.

参照カウント 0 のФайл (File)は, そのФайл (File)を参照する固定Посилання (Link)を持たないため, 動的なПосилання (Link)が失われてしまうと, 通常の方法ではアクセスできないことになるが, Файл (File)システム内の全てのФайл (File)に対するПосилання (Link)を取り出す方法によりアクセスすることは可能である.

Файл (File)のアクセス

Файл (File)は, 読込み(READ) / 書込み(WRITE) / 更新(UPDATE) のいずれかを指定してオープンするが, オープン時に他からの同一Файл (File)の同時オープンを制限するための以下のモード指定が可能である. デフォールトは共有モードとなるが, 通常は排他書込モードとすることが安全である.

他からのいかなる同時オープンを一切禁止するモード.
排他書込モード :
他からの書込み / 更新の同時オープンを一切禁止するモード.

1.6.6 Метадані та атрибути файлів (File Metadata)

Файл (File)システムの管理情報

個々のФайл (File)システムに対して, 以下の内容の管理情報を読み出すことができる. 

    typedef struct {
        H       fs_bsize;           /* 論理ブロックのバイト数 */

        H       fs_lang;            /* Файл (File)システムでの使用言語 */
        H       fs_level;           /* Файл (File)システムのアクセス管理レベル */

        W       fs_nfree;           /* 未使用ブロックの総数 */

        STIME   fs_ctime;           /* Файл (File)システムの生成日時 */

        TC      fs_locat[L_DLNM];   /* Пристрій (Device)所在名 */

  • fs_nfileはそのФайл (File)システムに登録可能な最大のФайл (File)数を示す. この値は, 最大のФайл (File)ID + 1に等しい.

  • fs_langはФайл (File)システムでの使用言語を示し, このФайл (File)システムで使用している文字コード体系を表わしている.

  • fs_levelは, Файл (File)システムのアクセス管理のレベルを表わすもので, 以下の値をとる.

    0:
    レベル0 -- アクセス管理なし
    1:
    レベル1 -- アクセス管理あり(隠し名なし)
    2:
    レベル2 -- アクセス管理あり(隠し名あり)

  • fs_nblk はФайл (File)システム全体の論理ブロックの総数であり, この値は論理ブロック番号の最大値 + 1 に等しい.

  • fs_nfreeは, 現時点の未使用論理ブロックの総数であり, このデータは動的に変動する.

  • fs_mtime, fs_ctime はそれぞれФайл (File)システムの最新更新日時と生成された日時で, 基準日(1985年1月1日00:00:00 GMT) からの秒数で表わす.

  • fs_name, fs_locatは, それぞれФайл (File)システムの生成時に設定される名称であり 20 文字に満たない場合は 0 が詰められている.

Файл (File)システムの管理情報はФайл (File)システムの生成時 ( フォーマット時 ) に設定され, 以後は未使用ブロックの総数 (fs_nfree) と, 最新のシステムブロックの更新日時 ( fs_mtime), Файл (File)システム名, およびПристрій (Device)所在名を除いて変更されることはない.

Файл (File)管理情報 :

本системний виклик (System Call)により, Файл (File)システム上に存在するすべてのФайл (File)(参照カウント = 0 のФайл (File)も含む)へのПосилання (Link)を取り出すことができる.

【Коди помилок】

ER_ADR      : адреса пам'яті(lnk)のアクセスは許されていない. 
ER_IO       : 入出力Помилкаが発生した. 
ER_NOFS     : Файл (File)(lnk)の属するФайл (File)システムは接続されていない. 
ER_NOEXS    : Файл (File)(lnk)より大きなФайл (File)IDを持つФайл (File)は存在していない. 
ER_NOSPC    : システムのОперативна пам'ять (Memory)領域が不足した.

map_rec
 
Запис (Record)のマップ

【Синтаксис / Прототип】

WERR    map_rec(W fd, W offset, B **addr, W size, W mode)

【Параметри】

W   fd      Файл (File)ディスクリプタ

W   offset  マップ開始バイトオフセット

B   **addr  マップされたОперативна пам'ять (Memory)адреса пам'ятіの格納領域

W   size    マップするバイトрозмір у байтах

W   mode    マップモード
    ( [ F_READ ] | [ F_WRITE ] | [ F_EXCUTE ] ) | [ F_COMMON ‖ F_SYSTEM ]
        F_READ      読み込み用マップ
        F_WRITE     書き込み用マップ
        F_EXECUTE   実行用マップ
        F_COMMON    共有Оперативна пам'ять (Memory)ー空間にマップ
        F_SYSTEM    システムОперативна пам'ять (Memory)ー空間にマップ

【Значення, що повертається】

＞0    Успішне виконання(マップID)
< 0      Помилка (Код помилки)

【Детальний опис】

オープンしたФайл (File)の現在Запис (Record)の offset から size バイトをОперативна пам'ять (Memory)ー空間上にマップする. マップされたЗапис (Record)の内容はОперативна пам'ять (Memory)ーとしてアクセスすることができる.

F_COMMON を指定した場合には, 共有Оперативна пам'ять (Memory)ー空間上にマップされる. この場合, すべてのПроцес (Process)からアクセス可能となる. F_SYSTEM を指定した場合には, システムОперативна пам'ять (Memory)ー空間上にマップされる. この場合, すべてのシステムПроцес (Process)からアクセス可能となる. マップしたПроцес (Process)自身であっても, 一般のприкладний додаток / програмаПроцес (Process)からはアクセスできない. したがって, прикладний додаток / програмаПроцес (Process)からはこの指定を使用すべきではない. F_COMMON,F_SYSTEM のいずれも指定しなければ, マップしたПроцес (Process)のローカルОперативна пам'ять (Memory)ー空間上にマップされる. この場合, マップしたПроцес (Process)以外からアクセスすることは出来ない.

マップされるадреса пам'ятіはシステムで決定され, прикладний додаток / програма側から指定することはできない.

マップモードの指定はオープンしたモードに矛盾してはいけない. (ER_FD)

  • F_READ オープンでは, F_WRITE でマップできない.
  • F_WRITE オープンでは, F_READ および F_EXCUTE でマップできない.

Посилання (Link)Запис (Record)はマップできない. (ER_REC)

マップ中は, 次の操作は禁止され ER_BUSY となる.

  • del_rec マップしているЗапис (Record)を対象とする場合.
  • wri_rec マップしているЗапис (Record)を対象とする場合.
  • trc_rec マップしているЗапис (Record)を対象とする場合.
  • xch_fil マップしているЗапис (Record)を含むФайл (File)を対象とする場合.

インプリメントに依存して以下の制限がつけられる場合がある.

  • マップ可能なФайл (File)システム(Пристрій (Device))
  • マップモードの組み合わせ
  • offset, および size の値

【Коди помилок】

ER_FD       : Файл (File)ディスクリプタは存在していない. 
            : マップモードとオープンモードが矛盾している. 
ER_REC      : 現在Запис (Record)はПосилання (Link)Запис (Record)である. 
ER_ADR      : адреса пам'яті(addr)のアクセスは許されていない. 
ER_ENDR     : 現在Запис (Record)は終端Запис (Record)である. 
ER_LOCK     : 現在Запис (Record)は他からロックされている. 
ER_IO       : 入出力Помилкаが発生した. 
ER_PAR      : параметриが不正である. 
ER_NOSPT    : システムの制限によりマップできない.

chg_fsm
 
Файл (File)システム接続モードの変更

【Синтаксис / Прототип】

WERR    chg_fsm( TC *dev, UW mode )

【Параметри】

TC  *dev    論理Пристрій (Device)名

UW  mode    接続モード (att_fls の mode と同じ)
            ( FS_SYNC ‖ FS_ASYN ‖ FS_RONLY )
            FS_SYNC     同期
            FS_ASYN     非同期
            FS_RONLY    書き込み禁止

【Значення, що повертається】

>= 0     Успішне виконання(変更前の接続モード)
< 0      Помилка (Код помилки)

【Детальний опис】

dev のПристрій (Device)の接続状態を mode で指定した接続モードに変更する. dev はすでに接続されているПристрій (Device)でなければならない. リターン値に変更前の接続モードを返す.

接続モードを変更するためには, dev に対する接続アクセス権が必要である.

接続モード変更前が書き込み可であった場合, 書き込み禁止に変更しても変更前に行われた map_rec() による書き込みモードのЗапис (Record)マップはそのまま有効となり, 書き込みも行われる. F_WRITE または F_UPDATE でオープンしているФайл (File)があるとき, 接続モードを書き込み禁止にすると, そのФайл (File)に対する wri_rec() 等の書き込みが ER_RONLY となる.

【Коди помилок】

ER_ACCES    : 論理Пристрій (Device)(dev)に接続アクセス権がない. 
ER_ADR      : адреса пам'яті(dev)のアクセスが許されていない. 
ER_IO       : 入出力Помилкаが発生した. 
ER_PAR      : параметриが不正である. 
ER_NOFS     : 論理Пристрій (Device)(dev)は, Файл (File)システムとして接続されていない.
