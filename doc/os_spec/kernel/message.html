1.2 Система повідомлень (Message Passing)

1.2.1 Повідомлення між процесами (Inter-Process Messages)

Кожен процес у системі BTRON має власну чергу повідомлень (Message Queue), через яку здійснюється міжпроцесна комунікація. Цей механізм використовується як для обміну даними між прикладними програмами, так і для системних сповіщень ядра (наприклад, повідомлень про завершення дочірніх процесів). З цієї причини основні формати системних повідомлень чітко регламентовані специфікацією.

Повідомлення відправляються в чергу цільового процесу за його ідентифікатором (PID). Ідентифікатор відправника також фіксується у системних метаданих.

Кожне повідомлення має стандартизовану структуру та класифікується полем msg_type на 31 тип (від 1 до 31). Бітова маска (Type Mask) дозволяє вибірково приймати або очищати групи повідомлень одного або кількох типів одночасно. 

typedef union {
    struct {
        W   pid;
        W   code;
    } ABORT;        /* Повідомлення про аварійне завершення процесу (Abort) */
    struct {
        W   pid;
        W   code;
    } EXIT;         /* Повідомлення про успішне завершення проце (Exit) */
    struct {
        W   pid;
        W   code;
    } TERM;         /* Повідомлення про примусове зупинення процесу (Term) */
    struct {
        W   code;
    } TMOUT;        /* Повідомлення про закінчення таймауту (Timeout) */
    struct {
        W   code;
    } SYSEVT;       /* Повідомлення про системну подію (SysEvt) */
    struct {
        UB  msg_str[32];
    } ANYMSG;       /* Загальний вміст користувацьких даних */
} MSGBODY;

typedef struct message {
    W       msg_type;   /* Тип повідомлення (msg_type) */
    W       msg_size;   /* Розмір тіла повідомлення (у байтах) */
    MSGBODY msg_body;   /* Тіло повідомлення (msg_body) */
} MESSAGE;

Черга повідомлень працює за принципом FIFO (First-In, First-Out). Якщо черга отримувача заповнена, відправник може або заблокуватися до звільнення місця, або негайно отримати код помилки у залежності від обраного режиму.

Зазвичай отримані повідомлення накопичуються у черзі та вилучаються за запитом прийому (rcv_msg). Проте реєстрація обробника повідомлень (Message Handler) дозволяє реалізувати асинхронне переривання для негайної обробки важливих системних або користувацьких подій.

rcv_msg
 
Отримання повідомлення (Receive Message)

【Синтаксис / Про тип】

WERR    rcv_msg(W t_mask, MESSAGE* msg, W msgsz, W opt)

【Параметри】

W        t_mask ПрийомЦільовий об'єкт / типТип повідомлення (msg_type)Маска
MESSAGE* msg    Прийом
W        msgsz  ПрийомУсі 
                включаючи заголовок повідомлення msgsz ≧ 8повинен відповідати умові.. 
W        opt    Прийом (WAIT ‖ NOWAIT ‖ WAIEVT) | (CLR ‖ NOCLR) | (CHECK)
WAIT :

Прийом, Очікувати.

NOWAIT :

Прийом, завершитися з помилкою..

WAIEVT :

Прийом, Чекати надходження повідомлення вказаного типу, Очікувати.

CLR :

Прийом.

NOCLR :

Прийом.

CHECK

Перевірити наявність повідомлення у черзі..

【Значення, що повертається】

＞0   Успіх(ПрийомПроцес ID)
＝0   Успіх(ПрийомПоточний процес)
＜0   Помилка(Помилка)

【Детальний опис】

Поточний процесВказаний типПрийом.

Прийом, msgsz лише в межах діапазону msg завершитися з помилкою.. У цьому випадку, CLR повідомлення залишається в буфері пам'яті.. Проте, msgsz < 8 якщо вказано msg у буфер нічого не записується.. Усі, , та стає активним..

CHECK якщо вказано, наступний станДія / Режимстає активним..

  1. Якщо в черзі немає жодного повідомлення, WAIT Крім того, WAIEVT При вказівці режимуОчікування, NOWAIT При вказівці режимузавершитися з помилкою..

  2. Якщо повідомлення вказаного типу присутнє,, msg Успіхзавершити.. CLR якщо вказано вилучення — вилучити з черги,, NOCLR якщо вказано збереження — залишити в черги..

  3. Якщо вказаний тип відсутній,, але в черзі є інші повідомлення,, заголовок повідомлення 8 ( msg_type та msg_size ) лише msg Успіхзавершити.. , CLR повідомлення залишається в черзі..

CHECK якщо вказано, Оскільки може бути повернуто заголовок іншого типу,, Прийом.

WAIEVT Вказівка даного режиму еквівалентна Дія / Режим WAIT та , Прийом, brk_msg() та Очікування. , Помилка ( ER_NOME ) завершити..

WAIEVT якщо вказано, t_mask = 0 можна вказати. , Прийом, Очікувати.

WAIEVT з даним режимомУсі 1 лише для однієї задачі, якщо кілька задач WAIEVT з даним режимом rcv_msg() та , лише для останньої викличущої задачі WAIEVT та . Інші задачі WAIT та та .

WAIEVT використовується графічною оболонкою BTRON Shell ( Менеджер вікон (Window Manager) ) wget_evt() Опція / Прапор. Прикладним програмам WAIEVT заборонено вказувати цей режим..
