1.2 Повідомлення (Message)管理

1.2.1 Процес (Process)間Повідомлення (Message)

Процес (Process)にはПовідомлення (Message)キューが付属しており, このПовідомлення (Message)キューを経由してПроцес (Process)間Повідомлення (Message)通信が行なわれる. このфункціонал / підсистемаは, Процес (Process)間でのприкладний додаток / програмаПовідомлення (Message)の通信だけではなく, 子Процес (Process)の終了Повідомлення (Message)等のシステムでの用途にも使用される. このため, いくつかのПовідомлення (Message)の形式はシステムで定義されている.

Повідомлення (Message)は, Процес (Process)に付属しているПовідомлення (Message)キューに送られ, 送信先はそのПроцес (Process) ID により指定される. また送信元も送信Процес (Process)のПроцес (Process) ID により識別される.

1 つのПовідомлення (Message)は以下の構造を持ち, msg_type により 1 〜 31 の 31 種のタイプに分けられている. さらに各タイプにビット対応したタイプマスクにより, Повідомлення (Message)の受信 / クリアにおいて, 対象とするПовідомлення (Message)のタイプ ( 複数 ) を指定できるようになっている. 

typedef union {
    struct {
        W   pid;
        W   code;
    } ABORT;        /* Процес (Process)の異常終了Повідомлення (Message) */
    struct {
        W   pid;
        W   code;
    } EXIT;         /* Процес (Process)のУспішне виконання終了Повідомлення (Message) */
    struct {
        W   pid;
        W   code;
    } TERM;         /* Процес (Process)の強制終了Повідомлення (Message) */
    struct {
        W   code;
    } TMOUT;        /* タイムアウトПовідомлення (Message) */
    struct {
        W   code;
    } SYSEVT;       /* システムПодія (Event)Повідомлення (Message) */
    struct {
        UB  msg_str[32];
    } ANYMSG;       /* その他一般 */
} MSGBODY;

typedef struct message {
    W       msg_type;   /* Повідомлення (Message)タイプ */
    W       msg_size;   /* Повідомлення (Message)本体розмір у байтах(バイト) */
    MSGBODY msg_body;   /* Повідомлення (Message)本体 */
} MESSAGE;

Процес (Process)のПовідомлення (Message)キューには他Процес (Process)からのПовідомлення (Message)以外にも自Процес (Process)から送信したПовідомлення (Message)も ( 送信先が自Процес (Process)の場合 ) 入り, この種のПовідомлення (Message)としてはタイムアウトПовідомлення (Message)がある. なお, 子Процес (Process)が終了した場合の終了Повідомлення (Message)もこのПовідомлення (Message)キューに入る.

Повідомлення (Message)キューは FIFO であり, 必ず送信順に入れられる. 送信時に相手のПовідомлення (Message)キューがフルの場合は, キューに空きができるまで待つか, Помилкаリターンするかを指定できる.

通常は, 受信したПовідомлення (Message)はПовідомлення (Message)キューに蓄えられ, Повідомлення (Message)の受信要求により取り出すが, Повідомлення (Message)ハンドラを定義することにより, 指定したタイプのПовідомлення (Message)を受信した場合に, 非同期な処理を行なうことが可能である. これは一種の割り込み処理として使用される.

システムПовідомлення (Message)は, システムで自動的に発生するПовідомлення (Message)であり, 以下に示す内容となる. これらは, 基本的にПовідомлення (Message)キューのオーバーフローの影響を受けず, 捨てられることはないようになっている. なお, 1 〜 7 のПовідомлення (Message)タイプを持つПовідомлення (Message)をприкладний додаток / програмаが送信することは特に禁止されていない.

MS_ABORT -- 子Процес (Process)の異常終了Повідомлення (Message)

Процес (Process)がシステムПомилкаにより異常終了させられた場合に, 親Процес (Process)に対して子Процес (Process)より自動的に送信される以下の内容のПовідомлення (Message)である. 

        W   1       /* タイプ = MS_ABORT */
        W   8       /* 本体のバイト数 */
        W   pid     /* 終了した子Процес (Process)のПроцес (Process) ID  */
        W   code    /* システムкод помилки */

code は発生したシステムПомилкаのコードであり, MH_TERM Повідомлення (Message)ハンドラによる異常終了の場合は, 0 となる.

MS_EXIT -- 子Процес (Process)のУспішне виконання終了Повідомлення (Message)

Процес (Process)が ext_prc() системний виклик (System Call)によりУспішне виконання終了した場合に, 親Процес (Process)に対して子Процес (Process)より自動的に送信される以下の内容のПовідомлення (Message)である. 

        W   2          /* タイプ = MS_EXIT */
        W   8          /* 本体のバイト数 */
        W   pid        /* 終了した子Процес (Process)のПроцес (Process) ID  */
        W   code       /* ext_prc ()で指定した終了コード */
MS_TERM -- 子Процес (Process)の強制終了Повідомлення (Message)

Процес (Process)が ter_prc() системний виклик (System Call)により他から強制終了させられた場合に, 親Процес (Process)に対して子Процес (Process)より自動的に送信される以下の内容のПовідомлення (Message)である. 

        W   3           /* タイプ = MS_TERM */
        W   8           /* 本体のバイト数 */
        W   pid         /* 終了した子Процес (Process)のПроцес (Process) ID  */
        W   code        /* ter_prc()で指定した終了コード */
MS_TMOUT -- 自Процес (Process)のタイムアウトПовідомлення (Message)

req_tmg() системний виклик (System Call)により要求したタイムアウトПовідомлення (Message)であり, 指定した時間後に, 自Процес (Process)に対して自動的に送信される以下の内容のПовідомлення (Message)である. 

        W   4           /* タイプ = MS_TMOUT */
        W   4           /* 本体のバイト数 */
        W   code        /* req_tmg ()で指定したコード */

1.2.3 Повідомлення (Message)ハンドラ

Повідомлення (Message)ハンドラとは, 受信したПовідомлення (Message)を現在実行中の処理と非同期に処理するための関数であり, Повідомлення (Message)のタイプと, 対応する関数を指定することにより定義される. 従って, Повідомлення (Message)の各タイプに対応した最大 31 種のПовідомлення (Message)ハンドラを同時に定義可能である.

Повідомлення (Message)ハンドラは以下に示す形で起動されて実行される.

  • 対応するタイプのПовідомлення (Message)を受信した場合, Повідомлення (Message)ハンドラは, Головна задача (Main Task)の現在の処理に割り込む形で実行される.

  • 何らかのсистемний виклик (System Call)による待ち状態の時にПовідомлення (Message)が送信された場合にもПовідомлення (Message)ハンドラは起動され, そのПроцес (Process)のГоловна задача (Main Task)が実行状態となる.
    この場合, Головна задача (Main Task)が実行中の長い待ちを伴ったсистемний виклик (System Call)は無条件に中断され, その結果は保証されない. 即ち, Повідомлення (Message)ハンドラが終了した時点で, 中断されたсистемний виклик (System Call)は ER_MINTR のПомилкаとして戻る.

  • Повідомлення (Message)ハンドラは通常のПроцес (Process)コードの一部として動作し, 実行できるсистемний виклик (System Call)等の制限はない.

  • Повідомлення (Message)ハンドラが終了した場合は, 通常, 割り込まれた位置からそのГоловна задача (Main Task)の実行が再開されるが, Повідомлення (Message)ハンドラから直接 longjmp () により, そのГоловна задача (Main Task)の任意の位置 ( setjmp で指定された位置 ) に実行を移行することも可能である.

  • Повідомлення (Message)ハンドラはネスティングしない. 即ち, 新たなПовідомлення (Message)ハンドラの起動 ( 別のПовідомлення (Message)タイプのものも含む ) は, 現在処理中のПовідомлення (Message)ハンドラの終了まで待たされる.

  • Повідомлення (Message)ハンドラが起動された場合, その起動の原因となったПовідомлення (Message)はПовідомлення (Message)キューから取り出され, 取り出されたПовідомлення (Message)のвказівник (Pointer)がハンドラのпараметриとして渡される.

  • Повідомлення (Message)ハンドラは, 必ず ret_msg () системний виклик (System Call)によって終了しなくてはいけない.

Повідомлення (Message)ハンドラは, 以下に示す形の関数として定義される. 

    VOID msg_hdr(W pid, MESSAGE *r_msg)
    {
    /*  pid は 送信したПроцес (Process)の ID . (自Процес (Process)の場合は 0) */
    /*  r_msg は受信したПовідомлення (Message)へのвказівник (Pointer)である. */

        受信Повідомлення (Message)の処理

        ret_msg (0);            /* 終了 (割り込んだ位置に戻る場合) */

        または

        ret_msg (1);            /* 終了 (任意の位置に移行する場合) */
        longjmp (reent, code);  /* reent へジャンプする */
    }

特殊なПовідомлення (Message)ハンドラとして以下のシステム定義のものが存在し, 使用することができる.

MH_NONE :

何もせずに, Повідомлення (Message)は無視される. この場合は, 例外的に待ちを含むсистемний виклик (System Call)は中断されない. これは, 単にある特定のタイプのПовідомлення (Message)をキューにも入れずに完全に無視するために使用される.

MH_BREAK :

何もせずに, Повідомлення (Message)は無視される. この場合は, 待ちを含むсистемний виклик (System Call)は中断され, ER_MINTR Помилкаが戻る. これは, タイムアウト等の処理に使用される.

MH_TERM :

自Процес (Process)を異常終了し, MS_ABORT Повідомлення (Message) ( код помилкиは 0 ) を親Процес (Process)に送信する.

1.2.5 системний виклик (System Call)

snd_msg
 
Повідомлення (Message)送信

【Синтаксис / Прототип】

ERR snd_msg(W pid, MESSAGE* msg, W opt)

【Параметри】

W        pid    送信先Процес (Process) ID
                   > 0   任意のПроцес (Process)
                   = 0   自Процес (Process)
                   =-1   親Процес (Process)
MESSAGE* msg    送信Повідомлення (Message)
W        opt    送信待ち属性 ( NOWAIT ‖ WAIT ‖ CONFM )
NOWAIT :

Повідомлення (Message)を送信先Процес (Process)のПовідомлення (Message)キューに入れた時点でУспішне виконання終了する. 送信先のПовідомлення (Message)キューに空きがない時はПомилка終了する.

WAIT :

Повідомлення (Message)を送信先Процес (Process)のПовідомлення (Message)キューに入れた時点でУспішне виконання終了する. Повідомлення (Message)キューに空きがない時は空きができるまで待つ. 待っている間に送信先Процес (Process)が終了した場合はПомилка終了する.

CONFM :

Повідомлення (Message)を送信先Процес (Process)のПовідомлення (Message)キューに入れ, 送信先Процес (Process)が送信したПовідомлення (Message)を受信, またはПовідомлення (Message)キューからクリアした時点でУспішне виконання終了する. それまで待つ.

rcv_msg() で CHECK 指定によりヘッダ部分のみを得た場合には, 受信したとみなされない. NOCLR 指定により受信した場合は, キューに残っていても受信したとみなされる. 待っている間に送信先Процес (Process)が終了した場合はПомилка終了する. 送信先が自Процес (Process)の場合, CONFM 指定はПомилкаとなる.

【Значення, що повертається】

= 0      Успішне виконання
< 0      Помилка (Код помилки)

【Детальний опис】

pid で指定したПроцес (Process)にПовідомлення (Message)を送信する.

【Коди помилок】

ER_ADR      : адреса пам'яті(msg)のアクセスは許されていない. 
ER_MINTR    : Повідомлення (Message)ハンドラが起動されたため待ち処理が中断された. 
ER_NOPRC    : Процес (Process)(pid)は存在していない. 
              Повідомлення (Message)キューの空き待ち, または確認待ちの間に送信先のПроцес (Process)が終了した. 
ER_NOSPC    : システムのОперативна пам'ять (Memory)領域が不足した
              (送信先のПовідомлення (Message)キューがフル(NOWAIT指定時)). 
ER_PAR      : параметриが不正である(オプション,Повідомлення (Message)タイプが不正). 
ER_SELF     : 自Процес (Process)を指定した(pid = 0 または自Процес (Process)のPID)(CONFM指定時). 
ER_SZOVR    : Повідомлення (Message)本体のрозмір у байтахがシステムの制限を越えた, または0以下である.
rcv_msg
 
Повідомлення (Message)受信

【Синтаксис / Прототип】

WERR    rcv_msg(W t_mask, MESSAGE* msg, W msgsz, W opt)

【Параметри】

W        t_mask 受信対象Повідомлення (Message)タイプマスク
MESSAGE* msg    受信Повідомлення (Message)格納領域
W        msgsz  受信Повідомлення (Message)格納領域全体のバイトрозмір у байтах
                Повідомлення (Message)のヘッダ部分も含むため msgsz ≧ 8でなくてはいけない. 
W        opt    受信属性 (WAIT ‖ NOWAIT ‖ WAIEVT) | (CLR ‖ NOCLR) | (CHECK)
WAIT :

指定タイプのПовідомлення (Message)を受信していない時は, Повідомлення (Message)が来るまで待つ.

NOWAIT :

指定タイプのПовідомлення (Message)を受信していない時は, Помилка終了する.

WAIEVT :

指定タイプのПовідомлення (Message)を受信していない時は, 指定タイプのПовідомлення (Message)が来るか, Подія (Event)発生まで待つ.

CLR :

Повідомлення (Message)を受信した後はそのПовідомлення (Message)をキューから取り除く.

NOCLR :

Повідомлення (Message)を受信した後もそのПовідомлення (Message)をキューに残しておく.

CHECK

Повідомлення (Message)の有無をチェックする.

【Значення, що повертається】

> 0      Успішне виконання(受信Повідомлення (Message)の送信元Процес (Process) ID)
= 0      Успішне виконання(受信Повідомлення (Message)の送信元は自Процес (Process))
< 0      Помилка (Код помилки)

【Детальний опис】

自Процес (Process)宛の指定したタイプのПовідомлення (Message)を受信する.

受信したПовідомлення (Message)が指定した領域に入り切らない場合は, msgsz の範囲内のみ msg の領域に格納されてПомилка終了する. この時は, CLR 指定があってもПовідомлення (Message)はバッファに残る. ただし, msgsz < 8 の時は msg の領域には何も格納されない. Повідомлення (Message)の全体が格納できなかった場合は, 格納されたПовідомлення (Message)のヘッダ部分から実際のПовідомлення (Message)розмір у байтахが判断できるので, そのПовідомлення (Message)が格納可能な十分な大きさの領域を用意して再度本системний виклик (System Call)を実行することになる.

CHECK 指定の時は, 次のような動作になる.

  1. Повідомлення (Message)が何も存在しない場合, WAIT または WAIEVT 指定時は待ち, NOWAIT 指定時はПомилка終了する.

  2. 指定したタイプのПовідомлення (Message)が存在している場合は, msg にПовідомлення (Message)を格納しУспішне виконання終了する. CLR 指定であればキューから取り除き, NOCLR 指定であればキューに残す.

  3. 指定したタイプのПовідомлення (Message)が存在せず, それ以外のПовідомлення (Message)が存在している場合は, Повідомлення (Message)の先頭 8 バイト ( msg_type と msg_size ) のみを msg に格納しУспішне виконання終了する. この場合, CLR 指定があってもПовідомлення (Message)はキューに残す.

CHECK 指定の時は, 指定したタイプ以外のПовідомлення (Message)が得られる可能性があるため, 受信したПовідомлення (Message)のタイプを必ずチェックする必要がある.

WAIEVT を指定は基本的な動作は WAIT 指定と同じであるが, Повідомлення (Message)が受信されていなくても, brk_msg() によりПодія (Event)発生が通知されると待ちが解除される. この場合, Помилка ( ER_NOME ) 終了する.

WAIEVT を指定した場合は, t_mask = 0 が指定できる. この場合, Повідомлення (Message)の受信は行われず, Подія (Event)発生が通知されるまで待つ.

WAIEVT を指定できるのは同時にはシステム全体で 1 つのЗадача (Task)のみで, 複数のЗадача (Task)が WAIEVT 指定で rcv_msg() を呼び出したときは, 最後に呼び出したЗадача (Task)の WAIEVT 指定のみが有効となる. 他のЗадача (Task)は WAIT と同じ扱いとなる.

WAIEVT は外殻 ( Менеджер вікон (Window Manager) ) の wget_evt() の実現のために用意されたオプションである. прикладний додаток / програмаは WAIEVT を指定してはいけない.

【Коди помилок】

ER_ADR      : адреса пам'яті(msg)のアクセスは許されていない. 
ER_MINTR    : Повідомлення (Message)ハンドラが起動されたため待ち処理が中断された. 
ER_NONE     : 指定したタイプ(t_mask)のПовідомлення (Message)は存在しない(NOWAIT指定時). 
ER_PAR      : параметриが不正である
              (msgsz が小さすぎる, 
               WAIEVT指定時以外 t_mask≦0, WAIEVT指定時 t_mask<0).
clr_msg
 
Повідомлення (Message)クリア

【Синтаксис / Прототип】

ERR clr_msg(W t_mask, W last_mask)

【Параметри】

W   t_mask      クリア対象Повідомлення (Message)タイプマスク
                = MM_ALL     全Повідомлення (Message)タイプ

W   last_mask   クリア終了Повідомлення (Message)タイプマスク
                = MM_NULL    対象はПовідомлення (Message)キューの最後まで
                = MM_ALL     Повідомлення (Message)を1つだけクリア

【Значення, що повертається】

= 0      Успішне виконання
< 0      Помилка (Код помилки)

【Детальний опис】

自Процес (Process)宛の指定したタイプの受信済みПовідомлення (Message)をクリアする.

自Процес (Process)のПовідомлення (Message)キューに受信済みのПовідомлення (Message)のうち, t_mask で指定したタイプのПовідомлення (Message)を last_mask で指定したタイプのПовідомлення (Message)の直前までクリアする. last_mask で指定したタイプのПовідомлення (Message)はクリアされないが, last_mask = MM_ALL の時は, 特別にПовідомлення (Message)を 1 つだけクリアすることを意味する.

t_mask と last_mask の指定例を以下に示す.

t_masklast_mask動作
MM_ALLMM_NULL 受信済みの全Повідомлення (Message)をクリア
− MM_ALL t_mask で指定したПовідомлення (Message)を 1 つだけクリア
MM_ALLMM_ALL 先頭のПовідомлення (Message)を1つだけクリア

【Коди помилок】

ER_PAR  : параметриが不正である(t_mask≦0, last_mask<0).
req_tmg
 
タイムアウトПовідомлення (Message)要求

【Синтаксис / Прототип】

ERR req_tmg(W time, W code)

【Параметри】

W   time    Повідомлення (Message)送信時間(ミリ秒)
W   code    タイムアウトПовідомлення (Message)のコード

【Значення, що повертається】

= 0      Успішне виконання
< 0      Помилка (Код помилки)

【Детальний опис】

自Процес (Process)宛に指定した時間後にタイムアウトПовідомлення (Message) ( MS_TMOUT ) を送信することを要求する.

このфункціонал / підсистемаは, Повідомлення (Message)ハンドラと組み合わせて特定の処理のタイムアウト監視などに使用される.

【Коди помилок】

ER_NOSPC    : システムのОперативна пам'ять (Memory)領域が不足した. 
ER_PAR      : параметриが不正である(time≦0).

【Синтаксис / Прототип】

     ERR can_tmg()

【Параметри】

なし

【Значення, що повертається】

すでに送信されてПовідомлення (Message)キューに入っているタイムアウトПовідомлення (Message)はクリアされない.

def_msg
 
Повідомлення (Message)ハンドラ定義

【Синтаксис / Прототип】

  ERR def_msg(W t_mask, FP msghdr)

【Параметри】

W   t_mask  対象Повідомлення (Message)タイプマスク

FP  msghdr  Повідомлення (Message)ハンドラ開始адреса пам'яті
            = NULL      Повідомлення (Message)ハンドラの定義解除
            = MH_NONE   システム定義ハンドラ(無視)
            = MH_BREAK  システム定義ハンドラ(処理中断)
            = MH_TERM   システム定義ハンドラ(Процес (Process)終了)

【Значення, що повертається】

= 0      Успішне виконання

同じタイプのПовідомлення (Message)に対するПовідомлення (Message)ハンドラがすでに定義されている場合には, 後から定義したПовідомлення (Message)ハンドラが有効となる.

ret_msg
 
Повідомлення (Message)ハンドラ終了

【Синтаксис / Прототип】

ERR ret_msg(W ret)

【Параметри】

W   ret リターン指定
＝0 :
Повідомлення (Message)ハンドラが割り込んだ位置から実行を再開し, 本системний виклик (System Call)からは戻らない.
待ちを含むсистемний виклик (System Call)の実行中に割り込んだ場合, そのсистемний виклик (System Call)の実行は保証されずに, Повідомлення (Message)ハンドラが起動されたことを示すкод помилкиがそのсистемний виклик (System Call)から戻る.
≠0 :
Повідомлення (Message)ハンドラが割り込んだ位置からは再開せずに, 本системний виклик (System Call)から戻って, そのまま実行を続行する. この場合, 通常はハンドラの最後で longjmp () により制御を他へ移行することになる.

【Значення, що повертається】

リターンしない(ret = 0 の時)
＝0     Успішне виконання(ret≠ 0 の時)

【Детальний опис】

Повідомлення (Message)ハンドラの実行を終了する.

Повідомлення (Message)ハンドラの最後には必ず本системний виклик (System Call)を実行しなくてはいけない. また, 本системний виклик (System Call)はПовідомлення (Message)ハンドラ内でのみ発行することができ, それ以外の部分で発行された時はシステムПомилкаとなる.

Повідомлення (Message)ハンドラの起動要求が多重に発生していた場合, 本системний виклик (System Call)の実行後に要求のあったПовідомлення (Message)ハンドラが起動する.

【Коди помилок】

発生しない.

brk_msg
 
Подія (Event)発生通知

【Синтаксис / Прототип】

ERR brk_msg()

【Параметри】

なし

【Значення, що повертається】

= 0      Успішне виконання

【Детальний опис】

WAIEVT 指定による rcv_msg() の待ちを解除する. brk_msg() を呼び出したとき WAIEVT 指定で待ちに入っているЗадача (Task)が無ければ, 待ち解除の要求を記録する. ただし, 待ち解除の要求回数は記録されない.

【Коди помилок】

発生しない.
