Розділ 4. Формат дискети та файлової системи BTRON FS

4.1 Огляд формату носіїв BTRON

Стандарт BTRON описує бінарну структуру розмітки фізичних носіїв даних (дискет, змінних дисків, твердотілих накопичувачів) та файлову систему BTRON FS, яка підтримує деревовидно-мережеву структуру Реальних та Віртуальних об'єктів (Real/Virtual Objects), фрагментацію блоків і вбудовані індекси записів.

Сектори дискети називаються фізичними блоками та є мінімальною одиницею фізичного доступу. Логічний блок (Logical Block) є одиницею логічної адресації та складається з n послідовних фізичних секторів. Стандартний розмір логічного блоку для дискет становить 512 або 1024 байти.

4.2 Структура файлової системи BTRON FS

4.2.1 Загальна схема розміщення блоків

Диск розділений на фізичні сектори. Перший сектор містить системний блок (System Block), за яким слідують таблиці файлів, таблиці фрагментів та область даних.

4.2.2 Структура системного блоку (System Block)

typedef struct {
    B   boot_code[32];  /* Завантажувальний код або сигнатура OS */
    TC  vol_name[12];   /* Назва тома/диска у TRON Code */
    UW  vol_id;         /* Унікальний ID тома */
    UH  blk_size;       /* Розмір блоку у байтах (512, 1024) */
    UW  total_blks;     /* Загальна кількість блоків на томі */
    UW  free_blks;      /* Кількість вільних блоків */
    UW  file_id_tbl;    /* Сектор початку таблиці ID файлів */
    UW  root_f_id;      /* ID кореневого об'єкта (Root Real Object) */
} SYSTEM_BLOCK;

4.2.3 Таблиця ідентифікаторів файлів (File ID Table)

typedef struct {
    UW  file_id;        /* Унікальний ідентифікатор файлу */
    UW  header_blk;     /* Номер першого блоку заголовка файлу (Header Block) */
    UW  file_size;      /* Розмір файлу у байтах */
    UH  attr;           /* Атрибути файлу (системний, лише для читання, захищений) */
} FILE_ID_ENTRY;

4.2.4 Таблиця коротких назв файлів (Short Name Table)

typedef struct {
    UW  file_id;        /* ID файлу */
    TC  short_name[8];  /* Коротке ім'я файлу у кодуванні TRON Code */
} SHORT_NAME_ENTRY;

4.2.5 Область зберігання тіл файлів (Data Area)

4.3 Внутрішня організація файлу BTRON

4.3.1 Загальна схема

Файл у BTRON FS складається із блоку заголовка файлу (Header Block), таблиці фрагментів (Fragment Table), індексів записів (Record Index) та блоків даних (Data Blocks).

4.3.2 Структура блоку заголовка файлу (Header Block)

typedef struct {
    UW  magic;          /* Сигнатура заголовка (0x4254524F = 'BTRO') */
    UW  file_id;        /* ID файлу */
    UW  rec_cnt;        /* Кількість записів у файлі */
    STIME ctime;        /* Час створення */
    STIME mtime;        /* Час останньої модифікації */
} HEADER_BLOCK;

4.3.3 Структура заголовка файлу (File Header)

Заголовок файлу містить розширені метадані: версію файлу, права доступу користувачів, довжину індексного блоку та вказівник на таблицю фрагментів.

4.3.4 Таблиця фрагментів (Fragment Table)

typedef struct {
    UW  start_blk;      /* Початковий сектор фрагмента на диску */
    UW  blk_cnt;        /* Кількість безперервних секторів у фрагменті */
} FRAGMENT_ENTRY;

4.3.5 Індекс записів файлу (Record Index)

Кожен запис у файлі BTRON ідентифікується індексом запису. При рівні індексу 0 (Index Level 0) блок заголовка може містити до 40 прямо за адресованих індексів записів. Якщо запис займає кілька блоків, за звичайним індексом слідує один або кілька з'єднувальних індексів (Continuation Index). 

/* Структурний формат запису індексу (8 байтів, Big-Endian) */
typedef struct {
    UB  rec_type;       /* Тип запису (0x80 = посилання, 0x81..0xFF = звичайні/з'єднувальні) */
    UB  rec_subtype;    /* Підтип запису */
    UH  start_off;      /* Зсув у байтах від початку логічного блоку (0..blk_size-1) */
    UW  rec_len;        /* Довжина запису у байтах */
    UB  cont_cnt;       /* Лічильник послідовних блоків (0..255) */
    UB  blk_addr[3];    /* 24-бітний номер логічного блоку даних */
} RECORD_INDEX_ENTRY;

4.3.6 Структура непрямих індексів (Indirect Index)

Непрямі індекси використовуються, коли рівень індексу (Index Level) > 0. Кожен елемент непрямого індексу має розмір 8 байтів та посилається на додатковий індексний блок: 

typedef struct {
    UW  valid_rec_cnt;  /* Кількість дійсних записів в індексному блоці */
    UW  blk_addr;       /* Номер логічного блоку індексного масиву */
} INDIRECT_INDEX_ENTRY;

Максимальна кількість записів залежить від рівня індексу:

Level 15 120 записів64 * 80 записів

4.3.7 Приклад розміщення індексів записів (Record Index Walkthrough)

Приклад доступу до запису #110 при рівні індексу Level 1:

  • Індексний блок A: 53 записи (64 елементи, з них 11 з'єднувальних).
  • Індексний блок B: 42 записи (50 елементів, з них 8 з'єднувальних).
  • Індексний блок C: 20 записів (20 елементів).

Для доступу до 110-го запису відраховується: 110 - 53 - 42 = 15. Система бере 15-й запис безпосередньо з індексного блоку C.

Якщо перед 10-м записом вставляється новий запис, індексний блок A розщеплюється на два рівні блоки A' та A'', і непрямий індекс оновлюється відповідним чином.

4.3.8 Структура блоків даних (Data Blocks)

Блоки даних містять безпосередньо вміст записів. Між сусідніми записами у межах одного логічного блоку розміщуються 2-байтові розділові коди (Separator Codes), які позначають розмір вільного простору. Сусідні вільні фрагменти автоматично об'єднуються.

Додаток A: Квазі-стандартний формат дискет (Semi-Standard Format)

Стандартний формат BTRON FS використовує порядок байтів Big-Endian. Для систем на базі процесів з архітектурою Little-Endian (x86 тощо) специфікація визначає Квазі-стандартний формат (Semi-Standard Floppy Format).

  • Символьні коди зберігаються як 16-бітні значення Little-Endian (молодший байт іде першим).
  • Усі 32-бітні цілі числа зберігаються у форматі Little-Endian.
  • Сигнатура тома у системному блоці для BTRON Standard дорівнює 0x42FE6400, а для Квазі-стандартного — 0xFE420064.

Додаток B: Приклад практичної реалізації драйвера дискети

Містить практичні приклади параметрів форматування 3.5" MF2HD (1.44 MB, 80 доріжок, 18 секторів) та 2HD (1.2 MB, 80 доріжок, 15 секторів).
